Некоторые сети блокируют или замедляют прокси, анализируя начало каждого зашифрованного соединения. В Throne есть несколько параметров, которые меняют то, как выглядит это начало. На этой странице объясняется, что делает каждый параметр, когда он может помочь и каковы его издержки.

В простом режиме `Предустановленные настройки` (Preset Settings), параметры `Фрагментация` (Fragment), `Включить фрагментацию записи TLS` (Enable TLS Record Fragment) и `TLS Tricks` в редакторе профиля, его кнопка `Доп. настройки` (Advanced Settings) и вариант `Custom` у мультиплексирования скрыты (только в расширенном режиме, см. [Простой и расширенный режим](@/get_started/configuration.ru.md#interface-mode)). Скрытые настройки сохраняют свои значения и продолжают действовать.

## Пресеты и настройки профиля {#presets}

Глобальные значения по умолчанию находятся в `Настройки` (Settings) → `Предустановленные настройки` (Preset Settings):

| Вкладка | Параметры — значение по умолчанию |
| --- | --- |
| `Мультиплексирование` (Multiplex) | sing-box: `Protocol` — `smux`; `Mode` — `Max Streams`; `Max Streams` — 8; `Max Connections` — 4; `Min Streams` — 4; `Padding` — выкл.; `TCP Brutal` — выкл.; `Вкл. по умолчанию` (Default On) — выкл. Xray: `Concurrency` — 8; `Max Connections` — пусто (без ограничения); `XUDP Concurrency` — 16; `UDP/443` — `Reject`; `Вкл. мультиплексирование по умолчанию` (Default Mux On) — выкл. |
| `TLS` | `Фрагментация TLS` (TLS Fragment): `Реализация` (Implementation) — `built-in`; `Размер` (Size) — `10-100`; `Пауза` (Sleep) — `2-5`; `Вкл. по умолчанию` — выкл. `TLS Tricks`: `Вкл. по умолчанию` — выкл. `uTLS`: `Fingerprint по умолчанию` (Default Fingerprint) — пусто. `Подмена TLS` (TLS Spoof): `Поддельный SNI` (Spoof SNI) — пусто; `Метод` (Method) — пусто; `Вкл. по умолчанию` — выкл. |
| `HTTP/2 & QUIC` | Тонкая настройка профилей на базе QUIC. Пустые поля оставляют значения ядра по умолчанию. |

Каждый профиль может переопределить пресеты в своём редакторе. Для фрагментации TLS, TLS Tricks, мультиплексирования и TLS Spoof есть три варианта:

| Вариант в профиле | Результат |
| --- | --- |
| `По умолчанию` (Keep Default) | Следует значению `Вкл. по умолчанию` в пресете. Его используют новые профили. |
| `Вкл.` (On) | Всегда включено для этого профиля. |
| `Выкл.` (Off) | Всегда выключено для этого профиля. |

Таким образом, `Вкл. по умолчанию` включает параметр только для профилей, у которых оставлен вариант `По умолчанию`. Начиная с версии 1.4.0, у мультиплексирования есть четвёртый вариант, `Custom`, — собственные настройки профиля. См. [Мультиплексирование](#multiplex).

Пресеты фрагментации TLS, TLS Tricks, TLS Spoof и мультиплексирования sing-box действуют только на профили, работающие на sing-box. У профилей `VLESS (Xray)` есть свой параметр мультиплексирования (`По умолчанию`, `Включено` (Enabled), `Выключено` (Disabled), а начиная с версии 1.4.0 и `Custom`), который следует пресетам Xray и значению `Вкл. мультиплексирование по умолчанию`. `Fingerprint по умолчанию` (Default Fingerprint) из uTLS действует на оба ядра. См. [sing-box или Xray](@/advanced/xray.ru.md#two-cores).

## Меняйте по одному параметру за раз {#one-at-a-time}

Каждый параметр противодействует определённому методу блокировки. Ни один из них не помогает везде, и каждый может сломать профиль, который до этого работал.

1. Выберите один профиль, который не работает или работает медленно.
2. В его редакторе включите один параметр.
3. Проверьте профиль: запустите тест задержки, затем откройте несколько сайтов.
4. Если ничего не улучшилось, верните параметру значение `По умолчанию` и попробуйте следующий.
5. Если параметр помогает большинству ваших профилей, включите для него `Вкл. по умолчанию` в `Предустановленные настройки`.

Мультиплексированию, его дополнению (padding), TCP Brutal и ECH также нужна поддержка на стороне сервера. О том, как тестировать профили, см. [Тестирование и автовыбор](@/guides/testing.ru.md#url-test).

## Фрагментация TLS {#tls-fragment}

Цензор часто читает имя сервера (SNI) в первом сообщении TLS-соединения — ClientHello. Фрагментация TLS разбивает это сообщение на маленькие части, чтобы простой фильтр не смог прочитать имя из одного пакета. Она помогает только против таких простых фильтров.

В редакторе профиля в разделе `Настройки маскировки TLS` (TLS Camouflage Settings) установите для `Фрагментация` (Fragment) значение `По умолчанию`, `Вкл.` или `Выкл.`. Способ разбиения выбирается в `Предустановленные настройки` → `TLS` → `Фрагментация TLS` → `Реализация`:

| `Реализация` | Как работает | Настройки |
| --- | --- | --- |
| `built-in` (по умолчанию) | sing-box разбивает ClientHello на несколько TCP-пакетов. | `Fallback Delay` в профиле, например `500ms`: пауза между частями, когда система не может её измерить. |
| `custom` | ClientHello отправляется частями случайного размера с короткими паузами между ними. | `Размер` (Size): байт в одной части, в виде диапазона (`10-100`). `Пауза` (Sleep): миллисекунд между частями, в виде диапазона (`2-5`). |

`Включить фрагментацию записи TLS` (Enable TLS Record Fragment) в том же разделе редактора — отдельный и более мягкий параметр. Он разбивает ClientHello не на несколько пакетов, а на несколько записей TLS. Попробуйте его раньше, чем `Фрагментация`.

**Издержки:** новые соединения устанавливаются медленнее. С реализацией `custom` для профиля отключается TCP Fast Open. Профили Naive поддерживают только реализацию `custom`.

Начиная с версии 1.4.0, фрагментировать подходящие соединения может и правило маршрутизации, например прямые соединения с сайтом, который фильтр блокирует по имени. Используйте расширенное правило с действием `route` или `route-options` и задайте `tls_fragment` (при необходимости вместе с `tls_fragment_fallback_delay`) или `tls_record_fragment`. См. [Маршрутизация](@/guides/routing.ru.md#advanced-rules).

## TLS tricks {#tls-tricks}

Параметр TLS tricks записывает имя сервера вперемешку заглавными и строчными буквами, например `ExAmPlE.com` вместо `example.com`. Серверы обычно не различают регистр, а фильтр, который ищет точное совпадение имени, может его пропустить.

Установите `TLS Tricks` в значение `Вкл.` в профиле (в разделе `Настройки маскировки TLS`) или отметьте `Предустановленные настройки` → `TLS` → `TLS Tricks` → `Вкл. по умолчанию` для всех профилей, у которых оставлен вариант `По умолчанию`.

**Издержки:** почти никаких. Не помогает против фильтров, которые не учитывают регистр.

## Отпечаток uTLS {#utls}

У каждого TLS-клиента есть характерный отпечаток: набор и порядок параметров в его ClientHello. Отпечаток обычного прокси-клиента легко распознать. uTLS вместо этого копирует отпечаток распространённого браузера или системы.

- **Для профиля:** `Fingerprint` в редакторе профиля. Ссылки для обмена часто задают его через `fp=`.
- **Глобально:** `Предустановленные настройки` → `TLS` → `uTLS` → `Fingerprint по умолчанию` (Default Fingerprint). Его используют профили без собственного отпечатка — на обоих ядрах (профили `VLESS (Xray)` — начиная с версии 1.4.0). Если поле пустое (по умолчанию), профили sing-box без отпечатка не используют uTLS, а профили Xray без отпечатка используют `chrome`. Профили Hysteria, TUIC, Juicity и Naive не используют uTLS.
- **Варианты:** `chrome`, `firefox`, `edge`, `safari`, `360`, `qq`, `ios`, `android`, `random`, `randomized`, а начиная с версии 1.4.0 — `unsafe`.
- **`unsafe`** отключает uTLS для профиля, даже если задан `Fingerprint по умолчанию`. Тогда ядро использует собственный TLS-клиент. Только в этом случае действует поле профиля `Наборы шифров` (Cipher Suites) (начиная с версии 1.4.0): имена наборов шифров TLS 1.2 через двоеточие. Оставьте его пустым, если этого не требует ваш сервер.

Профиль sing-box с REALITY, у которого вообще не задан отпечаток, использует `random`.

**Издержки:** небольшие. Если сервер перестал работать с одним отпечатком, попробуйте другой или очистите поле.

## Мультиплексирование {#multiplex}

Мультиплексирование (mux) передаёт много соединений внутри одного соединения с сервером. Тогда для открытия страницы нужно меньше новых соединений и рукопожатий, а наблюдатель видит меньше соединений.

- **Для профиля:** `Мультиплексирование` в редакторе профиля: `По умолчанию`, `Вкл.`, `Выкл.` или, начиная с версии 1.4.0, `Custom` (у профилей `VLESS (Xray)`: `По умолчанию`, `Включено`, `Выключено` или `Custom`). `По умолчанию` и `Вкл.` используют пресеты. При `Custom` нажмите `Configure` рядом со списком: окно `Custom Multiplex` (у Xray — `Custom Mux`) содержит те же поля, что и пресеты, и открывается с их значениями. Профиль из ссылки или подписки, в которой заданы собственные настройки mux, открывается с вариантом `Custom`.
- **Пресеты sing-box** (`Предустановленные настройки` → `Мультиплексирование` → `Sing-box`):
  - `Protocol`: `smux`, `yamux` или `h2mux`.
  - `Mode`: при `Max Streams` соединение используется повторно, пока не будет нести `Max Streams` потоков, затем открывается следующее. При `Max Connections` Throne держит не больше `Max Connections` соединений и открывает новое, только если наименее загруженное соединение уже несёт `Min Streams` потоков.
  - `Padding`: добавляет к мультиплексированному трафику дополнение (padding).
  - `TCP Brutal`, `Upload (Mb/s)` и `Download (Mb/s)`: см. [TCP Brutal](#tcp-brutal).
  - `Вкл. по умолчанию`.
- **Пресеты Xray** (`Предустановленные настройки` → `Мультиплексирование` → `Xray`):
  - `Concurrency`: сколько потоков несёт одно соединение, прежде чем откроется следующее. `0` означает значение Xray по умолчанию (8), а `-1` отправляет TCP в обход mux.
  - `Max Connections` (начиная с версии 1.4.0): не больше стольких соединений, отдельно для TCP и для XUDP. Когда каждое соединение несёт `Concurrency` потоков, новые потоки добавляются к наименее загруженному. Пустое поле — без ограничения.
  - `XUDP Concurrency` (начиная с версии 1.4.0): потоков UDP на одно соединение, в отдельных соединениях. `0` передаёт UDP через соединения TCP, а `-1` отправляет его в обход mux.
  - `UDP/443` (начиная с версии 1.4.0): UDP на порт 443, то есть в основном QUIC. `Reject` (значение Xray по умолчанию) заставляет браузеры вернуться к TCP, `Allow` пропускает его через mux, а `Skip` отправляет в обход mux.
  - `Вкл. мультиплексирование по умолчанию`.

До версии 1.4.0 пресеты sing-box состояли только из `Протокол` (Protocol), `Кол-во потоков` (Concurrency, теперь `Max Streams`), `Padding` и `Вкл. по умолчанию`, а `Padding` из пресета действовал на все профили с мультиплексированием. Теперь профиль с `Custom` использует собственный `Padding`.

Сервер должен поддерживать mux с тем же протоколом. Для дополнения данных тоже нужна поддержка сервера. Редактор профиля отключает мультиплексирование для профилей VLESS с flow `xtls-rprx-vision`. Профилям XDRIVE нужен mux, см. [XDRIVE](@/advanced/xray.ru.md#xdrive).

### TCP Brutal {#tcp-brutal}

`TCP Brutal` заставляет мультиплексированное соединение передавать данные с фиксированными скоростями, указанными в полях `Upload (Mb/s)` и `Download (Mb/s)`, даже при потере пакетов. Для этого нужен сервер с поддержкой TCP Brutal. С TCP Brutal все потоки идут через одно соединение, поэтому `Mode` и его значения не действуют.

Начиная с версии 1.4.0, TCP Brutal входит в настройки мультиплексирования sing-box: отметьте его в `Предустановленные настройки` для всех профилей, которые используют пресеты, или в окне `Custom Multiplex` отдельного профиля. Укажите обе скорости; отсутствующая отправляется как 1 Мбит/с. До версии 1.3.2 включительно в редакторе профиля были поля `Включить TCP Brutal` (Enable TCP Brutal), `Скорость скачивания (Brutal)` (Brutal Download Speed) и `Скорость загрузки (Brutal)` (Brutal Upload Speed). Если у профиля есть собственный TCP Brutal, но мультиплексирование не установлено в `Custom`, TCP Brutal не используется, а Throne предупреждает: «TCP Brutal only works with a custom multiplex. Set Multiplex to Custom.» (TCP Brutal работает только с пользовательским мультиплексированием; выберите Custom).

### Когда mux вредит {#mux-costs}

- Весь трафик идёт через одно соединение. Если оно зависает, зависают и все страницы и загрузки, которые через него идут.
- Множество параллельных соединений, например от торрент-клиента, при включённом mux может заставить Throne сильно нагружать процессор ([#1090](https://github.com/throneproj/Throne/issues/1090)). Отключите мультиплексирование для такого профиля.
- Первый запрос через новое mux-соединение занимает больше времени. При коротком тайм-ауте теста задержки рабочий профиль может быть отмечен как неработающий.

## ECH {#ech}

Encrypted Client Hello (ECH) шифрует имя сервера внутри ClientHello, чтобы наблюдатель не смог его прочитать. Работает, только если сервер поддерживает ECH. Пресета для ECH нет: он включается в каждом профиле отдельно.

1. Откройте профиль и нажмите `Доп. настройки` (Advanced Settings).
2. Отметьте `Вкл. ECH` (Enable ECH).
3. Необязательно: нажмите `ECH Config` и вставьте ECH-конфигурацию сервера. Если там остаётся `Не задано` (Not Set), ядро ищет конфигурацию в DNS.
4. Необязательно: в поле `ECH Query Name / Resolver` укажите домен, для которого нужно искать конфигурацию, если это не имя сервера. Начиная с версии 1.4.0, после `+` можно добавить DNS-сервер, например `cloudflare-ech.com+https://1.1.1.1/dns-query`. Тогда Throne обращается к этому серверу.
5. Нажмите `OK`, затем `OK` в редакторе профиля.

Если в этом поле нет DNS-сервера, начиная с версии 1.4.0 Throne ищет конфигурацию через прямой DNS. Раньше запрос шёл через тот самый прокси, для которого была нужна конфигурация, и мог завершиться ошибкой.

Начиная с версии 1.4.0, у профилей Xray есть собственное поле: `ECH Config List` в настройках TLS редактора профиля. Оно принимает ECH-конфигурацию сервера в Base64 или домен и сервер DNS поверх HTTPS, например `cloudflare-ech.com+https://8.8.8.8/dns-query`, чтобы Xray нашёл конфигурацию сам. Ссылки для обмена могут передавать ECH в параметре `ech=`; см. [ECH и закрепление сертификатов в ссылках](@/reference/protocols.ru.md#ech-links).

**Издержки:** профиль не работает, если сервер не поддерживает ECH или конфигурацию не удаётся найти.

## TLS spoof {#tls-spoof}

Некоторые фильтры пропускают соединения только к нескольким разрешённым именам и блокируют остальные. TLS spoof отправляет поддельный ClientHello с разрешённым именем непосредственно перед настоящим. Поддельное сообщение намеренно делается некорректным, поэтому сервер его игнорирует, а фильтр читает его и пропускает соединение.

Глобальные настройки находятся в `Предустановленные настройки` → `TLS` → `Подмена TLS` (TLS Spoof):

- `Поддельный SNI` (Spoof SNI): разрешённое имя, которое подставляется в поддельное сообщение.
- `Метод`: способ сделать поддельное сообщение некорректным: `wrong-sequence`, `wrong-checksum`, `wrong-ack`, `wrong-md5` или `wrong-timestamp`. Если поле пустое, используется значение ядра по умолчанию.
- `Вкл. по умолчанию`: подмена для каждого профиля, у которого оставлен вариант `По умолчанию`. Отметить этот флажок можно только после того, как вы укажете `Поддельный SNI`.

Для отдельного профиля откройте `Доп. настройки` и задайте `Подмена TLS` (`По умолчанию`, `Вкл.` или `Выкл.`), `Поддельный SNI` и `Метод`. Пустое поле берёт значение из пресета. Профиль с собственным `Поддельный SNI` выполняет подмену даже при варианте `По умолчанию`.

Чтобы выполнять подмену только для некоторых сайтов, используйте расширенное правило маршрутизации с действием `route` или `route-options` и задайте `tls_spoof` и `tls_spoof_method`. См. [Маршрутизация](@/guides/routing.ru.md#advanced-rules).

TLS spoof отправляет сырые пакеты, поэтому ядру нужны повышенные права:

- **Windows:** Throne должен работать от имени администратора — это нужно для драйвера WinDivert. TLS spoof недоступен в Windows ARM64.
- **Linux:** ядру нужны права root или возможности (capabilities) `CAP_NET_RAW` и `CAP_NET_ADMIN`.
- **macOS:** ядру нужны права root. Метод `wrong-timestamp` в macOS не работает.

Эти права ядро получает при выдаче прав для режима TUN. См. [Режим TUN](@/guides/tun_mode.ru.md#privileges).

**Издержки:** нужны повышенные права, а помогает он только против фильтров, которые пропускают некоторые имена.

## Настройка HTTP/2 и QUIC {#http2-quic}

`Предустановленные настройки` → `HTTP/2 & QUIC` задаёт значения по умолчанию для профилей Hysteria, TUIC и MASQUE: `Idle Timeout`, `Keep Alive Period`, `Stream Receive Window`, `Connection Receive Window`, `Max Concurrent Streams`, `Initial Packet Size` и `Отключить Path MTU Discovery` (Disable Path MTU Discovery). Пустые поля оставляют значения ядра по умолчанию. Профиль может переопределить их в `Доп. настройки` → `Параметры QUIC` (QUIC Parameters).

Оставляйте эти поля пустыми, если документация вашего сервера не требует других значений.

## Android {#android}

- Те же пресеты находятся в `Настройки` (Settings) → `Пресеты` (Presets): мультиплексирование (sing-box и Xray), фрагментация TLS Client Hello, TLS tricks, uTLS, а также HTTP/2 и QUIC. `Вкл. по умолчанию` (Default On) там называется `Включено по умолчанию` (On by default).
- У профилей есть тот же вариант `Оставить по умолчанию` (Keep default), а ECH задаётся в каждом профиле.
- После 2.0.3 пресеты мультиплексирования содержат те же поля, что и на компьютере, а в редакторе профиля у `Включить мультиплексор` (Enable multiplexer) появился вариант `Пользовательский` (Custom), который показывает поля мультиплексирования прямо под ним.
- Параметров фрагментации TLS в правилах маршрутизации в Throne для Android 2.0.2 нет.
- TLS spoof на Android недоступен.
