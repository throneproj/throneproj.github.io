Ядро Throne построено на sing-box и также содержит Xray. Большинство профилей работает на sing-box. Некоторые профили VLESS и все пользовательские конфигурации Xray работают на Xray. На этой странице объясняется, как Throne выбирает ядро, как изменить этот выбор для ссылок VLESS и как исправить ошибки подключения Reality.

В простом режиме большинство настроек с этой страницы скрыто: вкладки `Логирование` (Logging) и `Ядро` (Core), `Geo-файлы Xray` (Xray Geo Assets) и `Доверять системным сертификатам в Xray` (Trust System Certificates in Xray) в `Основные настройки` (Basic Settings), группа `Настройка` (Tuning) у XDRIVE и `Поделиться` (Share) → `Экспортировать конфиг` (Export config). См. [Простой и расширенный режим](@/get_started/configuration.ru.md#interface-mode).

## Два ядра в одном {#two-cores}

sing-box работает всегда. Он обслуживает локальный порт прокси, режим TUN, правила маршрутизации и DNS. Xray работает как помощник внутри того же ядра. Он запускается, только когда нужен запущенному профилю, например когда на Xray работает сам профиль, звено его цепочки или outbound правила маршрутизации. sing-box передаёт этот трафик в Xray через внутреннее локальное соединение, поэтому режим TUN, профили маршрутизации и настройки DNS работают одинаково с обоими ядрами.

На Xray работают такие профили:

| Столбец `Тип` (Type) | Откуда берутся |
| --- | --- |
| `VLESS (Xray)` | Ссылки `vless://` — в зависимости от [настройки «Предпочтение Xray для VLESS»](#vless-preference); outbound типа VLESS в Xray JSON; тип `VLESS (Xray)` в редакторе профиля. |
| `Custom Xray … Outbound` | Тип `Пользовательский (Xray outbound)` (Custom (Xray outbound)); остальные outbound из импортированного Xray JSON. |
| `Custom Xray Config` | Тип `Пользовательский (конфигурация Xray)` (Custom (Xray config)); импортированные списки полных конфигураций Xray. |

Все остальные профили, включая `VLESS`, работают на sing-box.

Некоторые возможности VLESS есть только в Xray. Ссылка `vless://`, которая использует одну из них, всегда импортируется как `VLESS (Xray)`, независимо от значения настройки:

- транспорт XHTTP (`type=xhttp`) и его настройки `extra`;
- шифрование VLESS (значение `encryption`, отличное от `none`);
- Finalmask;
- транспорт TCP (`raw`) с заголовком HTTP вместе с TLS.

Транспорт XDRIVE (начиная с версии 1.4.0) тоже есть только в Xray, но формата ссылки у него нет. См. [XDRIVE](#xdrive).

Сообщения Xray появляются на той же вкладке `Логи` (Logs). Их уровень детализации задаётся в `Настройки` (Settings) → `Основные настройки` (Basic Settings) → `Логирование` (Logging) → `Уровень логирования Xray` (Xray Log level).

## Выбор ядра для ссылок VLESS {#vless-preference}

Настройка `Настройки` → `Основные настройки` → `Ядро` (Core) → `Предпочтение Xray для VLESS` (Xray VLESS Preference) определяет, какое ядро получит ссылка `vless://` при импорте:

| Вариант | Ссылки, импортируемые как `VLESS (Xray)` |
| --- | --- |
| `XHTTP Only` | Только ссылки, которым нужна возможность, существующая лишь в Xray (см. список выше). Ссылки Reality остаются на sing-box. |
| `XHTTP And Reality` (по умолчанию) | Ссылки выше, а также все ссылки Reality. |
| `All VLESS` | Все ссылки `vless://`. |

Все остальные ссылки `vless://` становятся профилями `VLESS`, которые работают на sing-box.

Эта настройка действует только на ссылки `vless://`:

- **Clash / Mihomo YAML:** запись VLESS получает Xray, если использует XHTTP или шифрование VLESS. Начиная с версии 1.4.0, запись Reality поверх TCP, WebSocket или gRPC тоже получает Xray, если настройка не равна `XHTTP Only`. Остальные записи VLESS остаются на sing-box, в том числе при `All VLESS`.
- **Xray JSON:** каждый outbound типа VLESS становится `VLESS (Xray)`.
- **sing-box JSON:** outbound типа VLESS остаются на sing-box.
- **Редактор профиля:** вы сами выбираете `VLESS` или `VLESS (Xray)` в списке `Тип` (Type).

{% alert_info() %}
`XHTTP And Reality` стал значением по умолчанию в версии 1.2.0, когда был добавлен и вариант `All VLESS`. При обновлении Throne сохранённое значение не меняется. Если вы начали пользоваться Throne до версии 1.2.0, у вас может по-прежнему стоять `XHTTP Only`.
{% end %}

### После изменения настройки {#after-change}

Настройка влияет только на профили, которые вы импортируете после её изменения. Существующие профили сохраняют своё ядро. Чтобы перевести их на другое ядро:

- **Группа подписки:** обновите подписку (`Группы` (Groups) → `Обновить подписку` (Update subscription) или щёлкните правой кнопкой мыши по вкладке группы → `Обновить подписку`). Throne заменит затронутые профили новыми профилями другого типа, поэтому их прежние результаты тестов пропадут.
- **Профиль, добавленный из ссылки:** добавьте ссылку ещё раз, затем удалите старый профиль.
- **Профиль, созданный вручную:** его тип изменить нельзя. Создайте новый профиль с другим типом.

Если в окне `Доп. настройки` (Advanced) группы подписки включён параметр `Сохранять рабочие профили` (Keep working profiles), старые рабочие профили могут остаться рядом с новыми. Удалите их вручную.

### Какое ядро использует профиль? {#which-core}

Посмотрите на столбец `Тип` в списке профилей. `VLESS` работает на sing-box. `VLESS (Xray)`, `Custom Xray … Outbound` и `Custom Xray Config` работают на Xray.

Чтобы в этом столбце отображался и уровень безопасности, например Reality, включите `Настройки` → `Основные настройки` → `Интерфейс` (Style) → `Отображать безопасность конфигураций` (Show Config Security). Чтобы увидеть конфигурации, которые Throne генерирует для профиля, щёлкните по нему правой кнопкой мыши → `Поделиться` (Share) → `Экспортировать конфиг` (Export config) (начиная с версии 1.4.0). В окне есть вкладка `sing-box` и, если профиль использует Xray, вкладка `Xray`. `Копировать` (Copy) копирует открытую вкладку. До версии 1.3.2 включительно вместо этого были отдельные пункты `Экспортировать конфиг Sing-box` (Export Sing-box config) и `Экспортировать конфиг Xray` (Export Xray config).

## Ошибки Reality с новыми серверами Xray {#reality}

Новые серверы Xray отклоняют клиент Reality из sing-box. Тогда профиль не подключается, а в логе появляется `reality verification failed` ([#1780](https://github.com/throneproj/Throne/issues/1780)).

- Xray с 26.7.11 по 26.7.28 принимает только клиенты, которые сообщают о свежей версии Xray.
- Xray 26.9.9 и новее требует более нового обмена ключами (X25519MLKEM768), который клиент Reality из sing-box не предлагает.

Решение — запускать профиль на Xray:

1. Откройте `Настройки` → `Основные настройки` → `Ядро`.
2. Установите для параметра `Предпочтение Xray для VLESS` значение `XHTTP And Reality` или `All VLESS`.
3. Нажмите `OK`.
4. Обновите подписку или добавьте ссылку заново (см. [После изменения настройки](#after-change)).
5. Убедитесь, что в столбце `Тип` теперь указано `VLESS (Xray)`.

До версии 1.3.2 включительно это не помогало для записей Reality из подписки в формате Clash / Mihomo YAML, потому что они всегда оставались на sing-box. Начиная с версии 1.4.0, они следуют настройке, если используют TCP, WebSocket или gRPC. Для других транспортов используйте подписку в виде списка ссылок, если ваш провайдер её предлагает.

Если вы сами администрируете сервер Xray версии с 26.7.11 по 26.7.28, можно также добавить `"minClientVer": "0.0.0"` в `realitySettings` его VLESS-inbound. Это позволит подключаться старым клиентам. С Xray 26.9.9 и новее это не помогает.

## Старые настройки Xray {#old-settings}

Новые версии Xray отклоняют некоторые старые настройки, и профиль или конфигурация, которые их используют, не запускаются. Начиная с версии 1.4.0, Xray в Throne снова принимает их:

- VLESS и Trojan без TLS или другого шифрования к серверу в интернете. Новые версии Xray разрешают это только для частных адресов.
- `allowInsecure` в настройках TLS конфигурации Xray.
- Старые шифры Shadowsocks `aes-128-cfb`, `aes-256-cfb`, `chacha20` и `chacha20-ietf`, а также `none` или `plain`, в конфигурациях Xray.
- Типы безопасности VMess `none` и `zero` в конфигурациях Xray.

Предупреждения Xray об устаревших функциях появляются, только когда `Уровень логирования Xray` (Xray Log level) равен `debug`. Эти настройки менее безопасны или легче обнаруживаются. Используйте их только для серверов, которым они нужны.

## Доверие системным сертификатам {#system-ca}

Xray проверяет сертификаты серверов только по встроенным в него корневым сертификатам. Сервер, сертификат которого выдан корневым сертификатом, установленным вами, например корпоративным или самоподписанным, такую проверку не проходит. Начиная с версии 1.4.0, отметьте `Настройки` (Settings) → `Основные настройки` (Basic Settings) → `Безопасность` (Security) → `Доверять системным сертификатам в Xray` (Trust System Certificates in Xray) (по умолчанию выключено), чтобы Xray доверял и сертификатам, установленным в системе.

Параметр действует на настройки TLS всех профилей Xray и всех outbound в профилях `Пользовательский (Xray outbound)` и `Пользовательский (конфигурация Xray)`, включая соединение для скачивания в XHTTP. Outbound, в котором `useSystemCA` задан явно, сохраняет своё значение. Профили sing-box этот параметр не используют.

## XDRIVE {#xdrive}

Начиная с версии 1.4.0, профили `VLESS (Xray)` могут использовать транспорт XDRIVE. С XDRIVE Throne и сервер не соединяются друг с другом напрямую. Они обмениваются трафиком в виде файлов в хранилище, доступном обоим: в папке Google Drive, в другом хранилище с HTTP API или в папке на этом компьютере. Используйте его только с сервером, настроенным для XDRIVE, и с параметрами, которые дал его владелец.

У XDRIVE нет формата ссылки, потому что ссылка содержала бы секреты хранилища. Вместо этого импортируйте Xray JSON-конфигурацию сервера или ссылку Throne (`throne://add/…`). Ссылка `vless://` с `type=xdrive` отклоняется с сообщением «У XDRIVE нет формата ссылки. Импортируйте JSON-конфигурацию сервера.» (XDRIVE has no share-link format. Import the server's JSON configuration instead.). Когда вы делитесь профилем XDRIVE, Throne выдаёт его ссылку Throne.

Чтобы настроить XDRIVE в редакторе профиля, выберите `xdrive` в поле `Сеть` (Network). XDRIVE работает только с такими настройками VLESS, а при любом другом значении редактор показывает ошибку:

- `Шифрование` (Encryption): строка шифрования VLESS, которую выдаёт сервер; она начинается с `mlkem768x25519plus`.
- `Flow`: пусто.
- `Мультиплексирование` (Multiplex): `По умолчанию` (Keep Default), `Включено` (Enabled) или `Custom`, но не `Выключено` (Disabled). При `По умолчанию` Throne включает mux для XDRIVE, даже если `Вкл. мультиплексирование по умолчанию` (Default Mux On) выключено. Кроме того, Throne не применяет настройки mux, которые отправляют трафик в обход mux, например `Concurrency`, равное `-1`. См. [Мультиплексирование](@/advanced/presets.ru.md#multiplex).

Группа `Хранилище` (Storage):

| Поле | Что делает |
| --- | --- |
| `Сервис` (Service) | `google-drive` (по умолчанию): папка Google Drive. `template`: любое хранилище, HTTP API которого описывает `Шаблон` (Template). `local`: папка на этом компьютере. |
| `Папка` (Folder) | `google-drive`: идентификатор папки, общей для обеих сторон. `local`: путь к папке. `template`: значение, которое шаблон читает как `{folder}`. Обязательно для `google-drive` и `local`. |
| `Client ID`, `Client Secret`, `Refresh Token` | Только `google-drive`, все три обязательны: OAuth-клиент и токен обновления учётной записи Google, которой принадлежит папка. |
| `Секреты` (Secrets) | Только `template`: значения, которые шаблон читает как `{secret0}`, `{secret1}` и так далее, через запятую. |
| `Шаблон` (Template) | Только `template`, обязательно: операции auth, put, get, list и delete API хранилища в виде JSON. Нажмите кнопку, чтобы его изменить. |
| `Адрес фронта` (Front Address), `Порт фронта` (Front Port) | Необязательно, не для `local`: Throne подключается к API хранилища по этому адресу, а в TLS по-прежнему указывается хост API (разновидность domain fronting). `Порт фронта` по умолчанию 443 и используется только вместе с `Адрес фронта`. |

Группа `Настройка` (Tuning) содержит параметры времени и размера. Оставьте поле пустым, чтобы использовать значение Xray по умолчанию, которое показано в поле:

| Поле | По умолчанию в Xray | Что задаёт |
| --- | --- | --- |
| `Байт в сегменте` (Segment Bytes) | 524288 | Наибольший объём загрузки в одном файле, в байтах. Xray допускает не больше 16 MiB. |
| `Интервал сброса` (Flush Interval) | 20 | Сколько записи накапливаются перед загрузкой, в миллисекундах. |
| `Интервал опроса` (Poll Interval) | 50 | Самая короткая пауза между проверками новых файлов, в миллисекундах. |
| `Макс. интервал опроса` (Max Poll Interval) | 500 | Самая длинная пауза между проверками, пока соединение простаивает, в миллисекундах. |
| `Окно активного опроса` (Eager Window) | 2000 | Сколько после трафика проверки идут с самой короткой паузой, в миллисекундах. |
| `Тайм-аут пропуска` (Hole Timeout) | 30000 | Сколько ждать пропавший сегмент, прежде чем соединение завершится ошибкой, в миллисекундах. |
| `Время жизни сеанса` (Session TTL) | 300 | Сколько живёт простаивающий сеанс, прежде чем его файлы будут удалены, в секундах. |
| `Параллельность` (Concurrency) | 8 | Число параллельных запросов к хранилищу на одно соединение. Xray допускает не больше 64. |

## Xray в цепочках {#xray-in-chains}

В цепочке можно сочетать профили sing-box и Xray, но с двумя ограничениями:

- Все звенья Xray должны идти подряд. Трафик может перейти с sing-box на Xray и обратно только один раз: звенья sing-box, затем звенья Xray, затем снова звенья sing-box. Иначе профиль не запустится, а в логе появится «Too many core transitions» (слишком много переходов между ядрами).
- Профиль `Пользовательский (конфигурация Xray)` должен быть верхним звеном и не может находиться в одной цепочке с другими звеньями Xray, потому что цепочка может использовать только один экземпляр Xray.

Фронт-прокси и выходные прокси групп, а также WARP тоже считаются звеньями. См. [Цепочки прокси и пользовательские конфигурации](@/advanced/chains.ru.md#chains).

## Гео-файлы Xray {#geo-files}

У профиля `Пользовательский (конфигурация Xray)` могут быть собственные правила `routing` со значениями `geoip:` или `geosite:`. Для них Xray нужны файлы `geoip.dat` и `geosite.dat`. Другие профили и профили маршрутизации Throne эти файлы не используют: они работают с наборами правил (rule-set).

Если файлов нет, Throne показывает окно «Требуются Geo-файлы» (Geo asset files required) и предлагает их скачать. Нажмите `Да` (Yes), дождитесь окна «Загрузка Гео-файлов» (Geo assets installed), затем снова запустите профиль.

Адреса для скачивания находятся в `Настройки` → `Основные настройки` → `Прочее` (Miscellaneous) → `Geo-файлы Xray` (Xray Geo Assets), в полях `URL файла GeoIP` (GeoIP Asset URL) и `URL файла GeoSite` (GeoSite Asset URL). В их списках есть адреса четырёх источников: Loyalsoldier (весь мир и Китай, по умолчанию), Chocolate4U (Иран), runetfreedom (Россия) и v2fly. Берите оба файла из одного источника. Каждая кнопка `Загрузить` (Download) заново скачивает свой файл и заменяет старый.

Если правило ссылается на категорию, которой нет в файле, Throne показывает «Отсутствует Geo категория» (Geo asset missing category). Выберите источник, в котором есть эта категория, затем нажмите `Загрузить` для этого файла.

## Android {#android}

- Та же настройка находится в `Настройки` (Settings) → `Ядро` (Core) → `Настройки VLESS для Xray` (Xray VLESS preference), с вариантами `Только XHTTP` (XHTTP only), `XHTTP и Reality` (XHTTP and Reality) (по умолчанию) и `Все VLESS` (All VLESS). Она тоже действует только при импорте, поэтому после её изменения обновите подписку.
- Типы профилей — `VLESS` и `VLESS (Xray)`, а ограничения для Xray в цепочках те же.
- После 2.0.3 профили `VLESS (Xray)` на Android тоже могут использовать XDRIVE: выберите `XDRIVE` в поле `Сеть` (Network). Поля находятся в разделах `Настройки XDRIVE` (XDRIVE settings) и `Тонкая настройка XDRIVE` (XDRIVE tuning), а `Секреты` (Secrets) принимает по одному значению на строку.
- После 2.0.3 параметр `Настройки` (Settings) → `Ядро` (Core) → `Доверять системным сертификатам в Xray` (Trust system certificates in Xray) делает то же, что и на компьютере. Он доверяет корневым сертификатам, которые поставляются с Android, но не тем, что вы установили сами.
- Начиная с 2.0.2, Throne для Android сам загружает `geoip.dat` и `geosite.dat`, когда запускается или тестируется конфиг Xray с правилами `geoip:` или `geosite:`; ход загрузки виден в уведомлении. Источник выбирается в `Настройки` (Settings) → `Ядро` (Core) → `Геоданные Xray` (Xray geo assets): `Источник` (Source) предлагает те же четыре источника, что и десктопное приложение, или адреса `Пользовательский` (Custom). Чтобы загрузить файл заново, нажмите на него в списке `Файлы` (Files), а для обоих файлов — `Загрузить сейчас` (Download now).
