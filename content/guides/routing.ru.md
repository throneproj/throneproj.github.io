Маршрутизация решает, куда направляется каждое соединение: через прокси, напрямую или никуда. Встроенный профиль `Default` направляет всё через прокси, поэтому эта страница нужна, только если вы хотите иначе.

## Как работает маршрутизация {#how-routing-works}

Профиль маршрутизации — это список правил и параметр `Остальной трафик` (Everything else goes to): outbound для трафика, под который не подошло ни одно правило. Throne проверяет правила сверху вниз, и первое подходящее правило решает, куда пойдет соединение.

| Outbound | Куда идёт трафик |
| --- | --- |
| `Прокси` (Proxy) | Через запущенный профиль, а когда включен выход через WARP — еще и через него. |
| `Напрямую` (Direct) | Прямо в интернет. |
| `Блокировать` (Block) | Никуда. Соединение отклоняется. |
| `Прокси без выхода` (Proxy without exit) | Через запущенный профиль, но без выхода. См. [Обход выхода](@/advanced/warp.ru.md#warp-bypass). |
| Сохраненный профиль | Через этот профиль вместо запущенного. Только в правилах, см. [Правила](#advanced-rules). |

`Маршруты` (Routing) → `Выход через` (Exit through) добавляет к трафику `Прокси` последнее звено: `Cloudflare WARP` (см. [WARP](@/advanced/warp.ru.md)). `Выбранный профиль` (Selected profile) ничего не добавляет.

Одновременно активен один профиль маршрутизации. Переключить его можно в списке вверху меню `Маршруты` (Routing) или в меню трея → `Маршрутизация: <name>` (`Routing: <name>`). Активное подключение перезапускается с новыми правилами. Группа также может использовать собственный профиль маршрутизации, см. [Профиль маршрутизации для группы](#group-routing).

## Скачивание готовых профилей {#download-profiles}

1. Откройте `Маршруты` (Routing) → `Скачать профиль маршрутизации` (Download routing profile) и выберите `Китай` (China), `Иран` (Iran) или `Россия` (Russia).
2. Оставьте флажок `Автообновление` (Auto update) установленным и нажмите `OK`.
3. Выберите один из новых профилей вверху меню `Маршруты` (Routing). Само скачивание не делает его активным.

| Профиль | Что он делает |
| --- | --- |
| `Bypass China`, `Bypass Iran`, `Bypass Russia` | Проксирует всё, кроме сайтов и IP-адресов этой страны и вашей локальной сети. |
| `Proxy China Blocked`, `Proxy Russia Blocked` | Направляет всё напрямую, кроме сайтов, заблокированных в этой стране. |
| `Proxy Antizapret`, `Proxy Refilter` (Россия) | Направляет всё напрямую, кроме сайтов из списка блокировок Antizapret или Re:filter. |

Профиль «Bypass» подойдёт, если большинство сайтов, которые вы посещаете, находятся за рубежом. Профиль «Proxy … Blocked» пропускает через ваш сервер меньше трафика, но заблокированный сайт, которого нет в списке, не откроется.

Списки ведутся в репозитории [throneproj/routeprofiles](https://github.com/throneproj/routeprofiles). Если скачивание не удаётся, выберите другое `Зеркало наборов правил` (Remote Rule-set Mirror) (см. [Наборы правил](#rule-sets)) и повторите попытку.

## Профили маршрутизации {#profiles}

Профили маршрутизации находятся на вкладке `Маршрутизация` (Routing) окна `Настройки` (Settings) → `Настройки маршрутизации` (Routing Settings); это также последний пункт меню `Маршруты` (Routing). `Маршруты` → `Изменить текущий профиль` (Edit current profile) открывает в редакторе активный профиль, а если щелкнуть профиль в меню `Маршруты` правой кнопкой мыши, откроется этот профиль. `Сохранить` (Save) в редакторе сразу сохраняет профиль, и `Отмена` (Cancel) в окне `Настройки маршрутизации` этого не отменяет. Если подключение активно, нажмите `Перезапустить` (Restart) в уведомлении «Настройки изменены, перезапустите для применения» (Settings changed, restart to apply).

Есть три вида профилей:

- **Структурированные профили** — их редактируют в Throne с помощью [списков](#simple-rules) и [правил](#advanced-rules). Большинству пользователей нужны только они.
- **[Удалённые профили](#remote-profiles)** — скачиваются по URL.
- **[Raw-профили](#raw-profiles)** — пишутся в виде JSON sing-box.

Чтобы создать структурированный профиль:

1. На вкладке `Маршрутизация` (Routing) нажмите `Создать` (New) → `Структурированный профиль` (Structured profile).
2. Введите `Название` (Name) и задайте `Остальной трафик` (Everything else goes to).
3. Добавьте записи в списки или добавьте правила и нажмите `Сохранить` (Save).
4. Сделайте профиль активным в меню `Маршруты` (Routing).

Новый профиль начинается с правила `DNS-запросы` (DNS queries), которое передает DNS-запросы в DNS Throne. На вкладке `DNS` профилю можно задать собственные DNS-серверы, см. [DNS для профиля маршрутизации](@/guides/dns.ru.md#route-dns). Вкладка `Конечные точки` (Endpoints) появляется, если у вас есть профили OpenVPN или OpenConnect, и запускает их рядом с прокси, см. [раздельное туннелирование](@/advanced/vpn_profiles.ru.md#split-tunnel).

На вкладке `Маршрутизация` (Routing) есть также эти настройки:

| Настройка | Что делает |
| --- | --- |
| `Стратегия доменов` (Domain Strategy) → `Стратегия разрешения доменов по умолчанию` (Default Domain Strategy) | Предпочтение IPv4 или IPv6, когда Throne определяет адрес сервера или сайта, который идет напрямую. |
| `Стратегия доменов` (Domain Strategy) → `Стратегия разрешения доменов в запросах` (Resolve Domain Strategy) | Определяет IP-адрес каждого домена до применения правил, так что IP-правила срабатывают и для доменов. |
| `Обновления` (Updates) → `Зеркало наборов правил` (Remote Rule-set Mirror) | Откуда скачиваются наборы правил и профили, хранящиеся на GitHub. По умолчанию: `jsDelivr (Cloudflare)`. |

## Списки {#simple-rules}

У профиля есть четыре списка: `Напрямую` (Direct), `Прокси` (Proxy), `Блокировать` (Block) и `Прокси без выхода` (Proxy without exit). На вкладке `Правила` (Rules) профиля это строки с пометкой `Быстрый список` (Quick list); выберите такую строку, чтобы изменить список. Введите запись и нажмите `Enter` или `Добавить` (Add); если вставить несколько строк, добавятся все. Чтобы изменить запись, дважды щелкните по ней.

Тип строки без префикса определяется по ее виду: `example.com` становится суффиксом домена, `10.0.0.0/8` — диапазоном IP, `app.exe` — программой, а полный путь — путем к программе. Имена встроенных наборов правил и URL файлов `.srs` становятся наборами правил. Префикс задает тип явно:

| Строка | Что совпадает |
| --- | --- |
| `domain:example.com` | Только `example.com`. |
| `suffix:example.com` | `example.com` и все его поддомены. |
| `keyword:example` | Любой домен, который содержит `example`. |
| `regex:^cdn[0-9]*\.example\.com$` | Домены, подходящие под регулярное выражение (синтаксис Go RE2). |
| `ruleset:geosite-youtube` | Всё, что входит в [набор правил](#rule-sets), по имени или по URL файла `.srs`. |
| `ip:10.0.0.0/8` | Диапазон IP или отдельный адрес, например `1.2.3.4`. |
| `processName:Telegram.exe` | Программа по имени файла. |
| `processPath:C:\Program Files\App\app.exe` | Программа по полному пути. |

- Префиксы чувствительны к регистру: `processName`, а не `processname`. Имени программы без `.exe`, как в Linux и macOS, нужен префикс `processName:`.
- Имя процесса должно совпадать точно, с учётом регистра и `.exe` в Windows. Точное имя показывает [вкладка «Подключения»](#connections-tab).
- Запись, которую нельзя использовать, не принимается, и редактор называет причину, например если вместо домена указан URL с `https://`.

{% alert_info() %}
Правила для процессов видят только трафик, который доходит до Throne. В режиме системного прокси программы, игнорирующие прокси, до него не доходят, поэтому для правил процессов включайте `Режим TUN` (Tun mode). См. [Режим Tun](@/guides/tun_mode.ru.md#enable).
{% end %}

**Пример: проксировать все, кроме местных сайтов, и блокировать рекламу.** Установите для `Остальной трафик` (Everything else goes to) значение `Прокси` (Proxy). В список `Напрямую` (Direct):

```text
ruleset:geosite-ir
ruleset:geoip-ir
```

В список `Блокировать` (Block):

```text
ruleset:geosite-category-ads-all
```

Замените `ir` кодом своей страны, например `cn` или `ru`.

**Пример: через прокси идут только одна программа и один сайт.** Установите для `Остальной трафик` (Everything else goes to) значение `Напрямую` (Direct). В список `Прокси` (Proxy):

```text
processName:Telegram.exe
suffix:example.org
```

Каждый список работает как одно правило. По умолчанию они применяются в порядке `Напрямую`, `Прокси`, `Блокировать`, `Прокси без выхода`, и срабатывает первое совпадение, поэтому запись в списке `Прокси` ни на что не влияет, если более широкая запись в списке `Напрямую` подходит под тот же трафик. Чтобы сделать исключение, например проксировать `example.ir`, когда `geosite-ir` идет напрямую, добавьте `example.ir` в список `Прокси`, затем перетащите строку `Прокси` выше строки `Напрямую` на вкладке `Правила` (Rules).

## Правила {#advanced-rules}

Вкладка `Правила` (Rules) показывает все правила профиля по порядку. Четыре списка — это строки с пометкой `Быстрый список` (Quick list), а `Остальной трафик` (Everything else) всегда стоит последним.

- Чтобы изменить порядок, перетащите строку, нажмите `Alt+Up` или `Alt+Down` либо выберите в контекстном меню `Переместить в начало` (Move to top) или `Переместить в конец` (Move to bottom).
- Снимите флажок строки или нажмите `Space`, чтобы отключить правило, не удаляя его.
- `Дублировать` (Duplicate) и `Удалить` (Delete) действуют на выбранное правило, а поле фильтра находит правила по названию, домену или приложению.
- Правило с проблемой помечается, и профиль нельзя сохранить, пока правило не исправлено.

Чтобы добавить правило, нажмите `Новое правило` (New rule) и введите `Название` (Name). В разделе `Условия` (When) нажмите `+ Добавить условие` (+ Add condition), выберите условие и заполните его значения (`+ Добавить` (+ Add) добавляет еще одно значение). В разделе `Действие` (Then) выберите, что происходит с подходящим трафиком:

| Действие | Что делает |
| --- | --- |
| `Прокси` (Proxy), `Напрямую` (Direct), `Прокси без выхода` (Proxy without exit) | Направляет его туда. |
| `Блокировать` (Block) | Отклоняет его. `Способ отклонения` (Reject with) задает, как именно. |
| Конкретный профиль | Направляет его через сохраненный профиль, показанный как `[group] name`. Throne запускает этот профиль рядом с профилем, который запустили вы. |
| `Перехват DNS` (Hijack DNS) | Отвечает на DNS-запросы с помощью DNS Throne. |
| `Сниффинг` (Sniff) | Определяет протокол и домен соединения и переходит к следующему правилу. |
| `Разрешение домена` (Resolve) | Определяет IP-адрес домена и переходит дальше. |
| `Задать параметры маршрута` (Set route options) | Применяет `Параметры подключения` (Connection options) и переходит дальше. |
| `Обход` (Bypass) | Только в Linux с автоматическим перенаправлением (auto-redirect). См. [документацию sing-box](https://sing-box.sagernet.org/configuration/route/rule_action/). |

У вариантов, которые куда-либо направляют трафик, тоже есть `Параметры подключения` (Connection options). `Фрагментировать TLS-рукопожатие` (Fragment the TLS handshake) и `Разбить на TLS-записи` (Split into TLS records) работают как параметры [фрагментации TLS](@/advanced/presets.ru.md#tls-fragment) в профиле, что помогает прямым соединениям с сайтами, которые фильтр блокирует по имени; `Подмена SNI` (Spoof SNI) работает как [TLS spoof](@/advanced/presets.ru.md#tls-spoof).

| Условия | Что проверяют |
| --- | --- |
| `Домен` (Domain), `Суффикс домена` (Domain suffix), `Ключевое слово домена` (Domain keyword), `Регулярное выражение домена` (Domain regex) | Запрошенный домен. |
| `Диапазон IP` (IP range), `Частный IP` (Private IP) | Адрес назначения. |
| `Набор правил` (Rule-set) | Имена наборов правил или URL файлов `.srs`. |
| `Порт` (Port), `Диапазон портов` (Port range) | Порт назначения, например `443` или `1000:2000`. |
| `Диапазон IP источника` (Source IP range), `Порт источника` (Source port) и подобные | Откуда пришло соединение, например с другого устройства в вашей сети. |
| `Имя процесса` (Process name), `Путь процесса` (Process path), `Регулярное выражение пути процесса` (Process path regex) | Программа на этом компьютере. `Выбрать приложение` (Choose app) позволяет выбрать ее среди запущенных программ и программ, которые уже пользовались сетью. |
| `Сеть` (Network), `Протокол (по сниффингу)` (Protocol (sniffed)), `Версия IP` (IP version) | `tcp`, `udp` или `icmp`; обнаруженный протокол, например `tls` или `bittorrent`; `4` или `6`. |
| `Inbound` | `mixed-in` (порт прокси) или `tun-in` (режим Tun). |
| `Имя Wi-Fi (SSID)` (Wi-Fi name (SSID)), `Wi-Fi BSSID` | Сеть Wi-Fi, к которой вы подключены. Недоступно в macOS. |

Каждое условие — это блок, который срабатывает, если совпадает любое из его значений, а совпасть должны все блоки. Условия домена, IP и набора правил делят один блок; так же объединены два условия порта назначения, адреса источника и порты источника. `Инвертировать` (Invert) заставляет правило срабатывать на то, на что оно иначе не сработало бы. Правило без условий считается ошибкой, потому что оно перехватывало бы весь трафик. `sing-box JSON` внизу показывает правило в том виде, в каком его получает ядро.

Профили дополнительного ядра (Extra Core), полные пользовательские конфигурации и цепочки, которые содержат автовыбор, нельзя выбрать профилем правила.

## Наборы правил {#rule-sets}

Набор правил (rule-set) — это список доменов или диапазонов IP в отдельном файле. Используйте его как `ruleset:<name>` в списке или в условии `Набор правил` (Rule-set) правила.

- **Встроенные имена**: их более 2000. Имена, начинающиеся с `geosite-`, содержат домены, например `geosite-youtube` или `geosite-category-ads-all`. Имена, начинающиеся с `geoip-`, содержат диапазоны IP, например `geoip-ir` или `geoip-telegram`. Редактор подсказывает имена при вводе.
- **Собственные файлы**: URL любого бинарного набора правил sing-box. Имя файла должно содержать `.srs`.

Наборы правил скачиваются при запуске профиля. `Маршруты` (Routing) → `Обновить наборы правил` (Update rule-sets) скачивает свежие копии. Если GitHub в вашей сети заблокирован или работает медленно, измените `Настройки маршрутизации` (Routing Settings) → `Маршрутизация` (Routing) → `Обновления` (Updates) → `Зеркало наборов правил` (Remote Rule-set Mirror). Зеркало также применяется к списку рекламы для [блокировки рекламы](#adblock) и к профилям маршрутизации, которые хранятся на GitHub.

## Удалённые профили {#remote-profiles}

Удаленный профиль — это структурированный профиль, который Throne скачивает по URL, как профили из меню [Скачать профиль маршрутизации](#download-profiles). Провайдеры также могут передать его [ссылкой `throne://remoteroute/`](@/advanced/deeplinks.ru.md#remoteroute).

Чтобы добавить его, на вкладке `Маршрутизация` (Routing) нажмите `Создать` (New) → `Удаленный профиль` (Remote profile), введите `URL`, отметьте `Автообновление` (Auto update) и нажмите `Сохранить` (Save). `Предпросмотр` (Preview) показывает, что находится по этому адресу, а `Загрузить сейчас` (Fetch now) сразу заменяет правила его содержимым. По этому адресу может отдаваться ссылка `throne://route/`, ее текст в Base64 или JSON профиля. Raw-профили не могут быть удаленными.

Для автоматических обновлений нужен также параметр `Настройки маршрутизации` (Routing Settings) → `Маршрутизация` (Routing) → `Обновления` (Updates) → `Автообновление профилей маршрутизации` (Routing profiles auto update) → `Включить` (Enable), который по умолчанию выключен. Чтобы обновить профиль сразу, нажмите `Обновить` (Update) на вкладке `Маршрутизация` (Routing).

{% alert_warning() %}
Обновление заменяет правила и `Остальной трафик` (Everything else goes to), поэтому ваши изменения в профиле теряются. Чтобы настроить удаленный профиль под себя, клонируйте его кнопкой `Дублировать` (Clone) и снимите в копии флажок `Автообновление` (Auto update). Отключенные вами правила и собственные настройки DNS профиля сохраняются.
{% end %}

## Профиль маршрутизации для группы {#group-routing}

Группа может подключаться с собственным профилем маршрутизации вместо профиля из меню `Маршруты` (Routing). Например, серверы одного провайдера могут использовать `Bypass Iran`, а все остальные группы — `Default`.

1. Щелкните вкладку группы правой кнопкой мыши и выберите `Изменить группу` (Edit group).
2. Выберите `Профиль маршрутизации` (Routing Profile). Вариант `По умолчанию (…)` (Default (…)) следует меню `Маршруты` (Routing).
3. Нажмите `OK`.

Решает группа профиля, который вы запускаете. Для цепочки или автовыбора это группа самой цепочки или автовыбора, а не входящих в них профилей. Заголовок окна и всплывающая подсказка значка в трее показывают используемый профиль маршрутизации, а [вкладка «Подключения»](#connections-tab) изменяет именно его. Профиль маршрутизации группы приносит с собой и свои [настройки DNS](@/guides/dns.ru.md#route-dns), если они у него есть.

### Из подписки {#subscription-routing}

Некоторые провайдеры передают вместе с подпиской профиль маршрутизации в формате Happ. Чтобы использовать его, откройте параметры группы, отметьте `Использовать профиль маршрутизации из подписки` (Use the subscription's routing profile) в разделе `Подписка` (Subscription), нажмите `OK` и обновите подписку.

Throne сохраняет его как структурированный профиль маршрутизации с названием, которое дал провайдер. Если у группы `Профиль маршрутизации` (Routing Profile) — `По умолчанию (…)` (Default (…)), новый профиль становится профилем маршрутизации группы. Каждое обновление заменяет его правила. Настройки DNS из подписки никогда не используются.

- Чтобы изменить его насовсем, клонируйте его кнопкой `Дублировать` (Clone) и выберите клон в поле `Профиль маршрутизации` (Routing Profile) группы.
- Профиль принадлежит группе. При удалении группы удаляется и он.

## Raw-профили {#raw-profiles}

Raw-профиль — это полный объект `route` sing-box в формате JSON для возможностей, которых нет в редакторе правил. Создайте его кнопкой `Создать` (New) → `JSON-профиль` (Raw profile).

Outbound указываются числами: `-1` — это `proxy`, `-2` — `direct`, `-5` — `warp-bypass` (`Прокси без выхода`), а ID профиля — этот сохраненный профиль. После `"outbound":` редактор подсказывает ваши профили. Если `final` отсутствует, Throne использует `proxy`.

Имена встроенных наборов правил в raw-профилях не определены, и Throne не добавляет шаг DNS, который получают структурированные профили. Для режима Tun начинайте правила так:

```json
{
  "rules": [
    { "action": "sniff" },
    { "protocol": "dns", "action": "hijack-dns" },
    { "domain_suffix": ["example.com"], "outbound": -2 }
  ],
  "final": -1
}
```

`Запретить изменения` (Prevent modifications) использует JSON точно в том виде, в каком он написан, что может сломать DNS, профили Xray и цепочки. `Блокировать рекламу` (Block ads), `Включить DNS-маршрутизацию` (Enable DNS routing) и действия вкладки «Подключения» не работают с raw-профилями, а Throne для Android не может их использовать.

## Вкладка «Подключения» {#connections-tab}

Вкладка `Подключения` (Connections) внизу главного окна показывает открытые соединения, сгруппированные по программам, с адресом назначения, протоколом, outbound и объёмом трафика. Наведите курсор на столбец `Outbound`, чтобы увидеть правило, которое сработало для соединения; `final` означает, что ни одно правило не сработало.

Щелкните соединение правой кнопкой мыши, чтобы изменить, куда идет такой трафик в используемом профиле маршрутизации:

- `Напрямую` (Direct), `Прокси` (Proxy) или `Блокировать` (Block) показывают список целей с флажками: каждый уровень домена, например `*.example.com`, название сайта как ключевое слово, IP-адрес, если у соединения нет домена, и программу. Отмеченная цель добавляется в этот список и удаляется из других списков; если снять отметку, цель удаляется.
- `Другой профиль` (Specific profile) делает то же самое, но направляет цели через выбранный вами профиль.

Затем нажмите `Перезапустить` (Restart) в уведомлении «Настройки изменены, перезапустите для применения» (Settings changed, restart to apply). Цель добавляется в уже существующее правило этого списка. Если список был пустым, его новое правило добавляется в конец, где более широкое правило выше может сработать первым, поэтому проверьте порядок на вкладке `Правила` (Rules).

Эти действия недоступны для raw-профилей, для профилей с `Запретить изменения` (Prevent modifications), для удаленных профилей с `Автообновление` (Auto update), для профилей, которые обновляет подписка, а также пока открыто окно `Настройки маршрутизации` (Routing Settings). Чтобы изменить удаленный профиль или профиль из подписки, сначала клонируйте его, см. [Удаленные профили](#remote-profiles) и [Из подписки](#subscription-routing).

Если вкладки нет, включите `Настройки` (Settings) → `Основные настройки` (Basic Settings) → `Ядро` (Core) → `Статистика` (Statistics) → `Включить статистику подключений` (Enable connection statistics).

## Проверка маршрута {#route-lookup}

`Маршруты` (Routing) → `Поиск маршрута` (Route lookup) показывает, куда пошло бы соединение, не устанавливая его. Введите `Процесс` (Process), `Домен` (Domain) или `IP-адрес` (IP address), при необходимости измените `Порт` (Port), `Сеть` (Network) и `Распознанный протокол` (Sniffed protocol) и нажмите `Проверить` (Test). Результат называет outbound и правило, которое приняло решение, и показывает все правила, через которые соединение прошло до него.

- Пока профиль запущен, проверяется работающая конфигурация. Иначе выберите `Профиль маршрутизации` (Routing profile): Throne собирает конфигурацию, с которой он запустился бы, пропускает правила конечных точек и разрешает домены через системный резолвер.
- `Выбрать` (Pick) рядом с полем `Процесс` показывает запущенные программы и те, что уже подключались, или позволяет выбрать файл.

## Блокировка рекламы {#adblock}

`Маршруты` (Routing) → `Блокировать рекламу` (Block ads) блокирует рекламу в активном структурированном или удаленном профиле с помощью списка `adblocksingbox` из проекта 217heidai/adblockfilters. Он срабатывает раньше ваших собственных правил, поэтому реклама блокируется и в прямом, и в проксируемом трафике.

Если какой-то сайт перестал работать, выключите `Блокировать рекламу`, чтобы проверить, не блокирует ли его список. Чтобы блокировать рекламу только в одном профиле, вместо этого добавьте `ruleset:geosite-category-ads-all` в его список `Блокировать` (Block).

## Обмен профилями {#share-profiles}

Выберите профиль на вкладке `Маршрутизация` (Routing) и нажмите `Экспорт` (Export) (`Ctrl+C`), чтобы скопировать его как ссылку `throne://route/`.

Чтобы импортировать профиль, щелкните ссылку или скопируйте ее и нажмите `Ctrl+V` в главном окне. Профиль добавится, но не станет активным. `Импорт` (Import) (`Ctrl+V`) на вкладке `Маршрутизация` (Routing) также выбирает его, поэтому он станет активным, когда вы нажмете `OK`.

Ссылка содержит название, `Остальной трафик` (Everything else goes to), правила (включая отключенные) и собственные настройки DNS профиля. Правила, которые направляют трафик в сохраненный профиль, ссылаются на него по имени; если на другом устройстве профиля с таким именем нет, они используют `Прокси`. Конечные точки OpenVPN и OpenConnect передаются без учетных данных. Формат ссылки описан на странице [Глубокие ссылки](@/advanced/deeplinks.ru.md#route).

## На Android {#android}

В Throne для Android есть те же профили маршрутизации, правила и наборы правил. Откройте `Маршруты` (Routing) в боковом меню и нажмите на профиль, чтобы сделать его активным. Отличия:

- **Правила для приложений.** Поле `Приложения` (Apps) проверяет приложения Android; `Неизвестные приложения` (Unknown apps) — соединения, приложение которых не удаётся определить. `Регулярное выражение имени пакета` (Package name regex) проверяет имена пакетов. На компьютере эти правила никогда не срабатывают.
- **Правила для сети.** `Тип сети` (Network type) проверяет Wi-Fi, мобильную сеть или Ethernet, а `Лимитная сеть` (Metered network) — лимитные сети. Версия для компьютера пропускает такие правила при импорте ссылки.
- **Правила для Wi-Fi** требуют доступа к местоположению с вариантом «Разрешить в любом режиме» (Allow all the time) и включённой геолокации.
- **Raw-профили** и конечные точки VPN из импортированных ссылок не поддерживаются.
- `AdBlock` и `Автообновление удалённых профилей` (Auto update remote profiles) находятся в `Настройки` (Settings) → `Маршрутизация` (Routing).
- Если набор правил не удаётся скачать, `Всё равно подключиться` (Connect anyway) подключает без него. Его правила ни с чем не совпадают, пока он не будет скачан через прокси.
