Throne отправляет ваш трафик туда, куда указывают ваши профили и правила маршрутизации. На этой странице описано, что Throne отправляет по собственной инициативе: сведения об устройстве для подписок (HWID), сетевые запросы, которые приложение выполняет само, и кто может пользоваться его локальным портом прокси и Throne API. Throne не отправляет статистику использования и не загружает логи или аварийные дампы.

## HWID и сведения об устройстве {#hwid}

Некоторые провайдеры хотят знать, какое устройство запрашивает подписку. Throne может отправлять вместе с запросами подписки четыре заголовка. По умолчанию это выключено.

| Заголовок | Windows | Linux | macOS |
| --- | --- | --- | --- |
| `x-hwid` | `MachineGuid` Windows | Содержимое `/etc/machine-id` (или `/var/lib/dbus/machine-id`). Если нет ни того ни другого — идентификатор, который Throne создаёт один раз (начиная с 1.4.0) | Аппаратный UUID компьютера Mac |
| `x-device-os` | `Windows` | `Linux` | `macOS` |
| `x-ver-os` | Версия Windows, например `10.0.26100` | Версия ядра | Версия macOS, например `14.5` |
| `x-device-model` | Модель компьютера (и материнской платы), которую сообщает Windows | Название дистрибутива, например `Ubuntu 24.04.1 LTS` | Название и версия macOS, например `macOS Sonoma (14.5)` |

Чтобы включить эту функцию:

1. Откройте `Настройки` (Settings) → `Основные настройки` (Basic Settings) → `Подписка` (Subscription).
2. Установите флажок `Включить отправку HWID, модели устройства и версии ОС при обновлении подписки` (Enable sending HWID, device model, and OS version when updating subscription). Этот и остальные параметры ниже доступны только в расширенном режиме (см. [Простой и расширенный режим](@/get_started/configuration.ru.md#interface-mode)).
3. Нажмите `ОК` (OK).

Наведите указатель на флажок, чтобы увидеть значения, которые Throne определил на вашем компьютере.

**Linux:** начиная с 1.4.0 в системе без действительного идентификатора машины, например в контейнере, Throne один раз создаёт случайный идентификатор и хранит его в файле `hwid` в папке конфигурации, доступном для чтения только вам, чтобы идентификатор не менялся. Если удалить файл, Throne создаст новый идентификатор. Если записать файл не удаётся, Throne не отправляет идентификатор. Для headless Throne см. также [Идентификатор устройства](@/headless/_index.ru.md#device-id).

- Throne отправляет эти заголовки только с запросами подписки и никогда — с другими запросами.
- `Указать параметры системы вручную (опционально)` (Custom System Parameters (optional)) заменяет значения, которые отправляет Throne. Используйте формат `hwid=value,os=value,osVersion=value,model=value` и указывайте только те значения, которые хотите заменить.
- Каждая группа подписки может решать сама: выберите `Группы` (Groups) → `Редактировать текущую группу` (Edit current Group) и нажмите `Доп. настройки` (Advanced) в разделе `Подписка` (Subscription). `Отправлять HWID` (Send HWID) принимает значения `По умолчанию` (Keep Default, следовать настройке выше), `Вкл.` (On) или `Выкл.` (Off). Поля `HWID`, `ОС` (OS), `Версия ОС` (OS Version) и `Модель устройства` (Device Model) заменяют значения только для этой группы.
- Каждый запрос подписки также отправляет User-Agent: `Throne/<version>`, например `Throne/1.3.1`, если вы не задали другой `User Agent` на той же вкладке или для группы.

О том, когда провайдеру нужны эти настройки, см. [User-Agent и HWID](@/guides/subscriptions.ru.md#user-agent-and-hwid).

**Android:** в `Настройки` (Settings) → `Подписки` (Subscriptions) есть такой же переключатель (по умолчанию выключен) и `Пользовательские параметры HWID (необязательно)` (Custom HWID parameters (optional)). Throne для Android отправляет в качестве HWID идентификатор Android ID (`ANDROID_ID`). Если Android ID недоступен, приложение один раз создаёт случайный идентификатор и в дальнейшем отправляет его. В качестве ОС отправляется `Android`, а также версия Android и модель устройства. User-Agent по умолчанию — `Throne/Android/<version>`.

## Сетевые запросы {#network-requests}

Помимо трафика ваших приложений, Throne отправляет запросы, перечисленные в таблице ниже. Многие из них подчиняются «правилу `Использовать прокси`» (Use proxy):

- По умолчанию они идут напрямую.
- Если включён параметр `Настройки` → `Основные настройки` → `Прочее` (Miscellaneous) → `Использовать прокси` (Use proxy) или включён `Системный прокси` (System Proxy), они идут через локальный порт прокси Throne. В простом режиме `Использовать прокси` находится на вкладке `Общие` (Common), в группе `Настройки сети` (Network Settings).
- Если они должны идти через локальный порт прокси, но ни один профиль не запущен, они завершаются ошибкой «Запрос через прокси, но профиль не запущен.» («Request with proxy but no profile started.»).
- Начиная с 1.4.0, если включён параметр `Отключить mixed inbound` (Disable Mixed Inbound), локального порта прокси нет. Пока включён режим TUN, запросы, которые должны идти через этот порт, уходят как трафик любого другого приложения, и их направляет режим TUN. Если режим TUN выключен, они завершаются ошибкой «Request with proxy but the mixed inbound is disabled and Tun Mode is off.» (запрос через прокси, но mixed inbound отключён и режим TUN выключен).

Запрос, который идёт через локальный порт прокси, попадает в Throne так же, как трафик любого другого приложения, поэтому, куда он пойдёт дальше, решает ваш профиль маршрутизации.

| Запрос | Когда | Куда | Маршрут |
| --- | --- | --- | --- |
| Обновление подписки | Когда вы добавляете или обновляете подписку, а также по расписанию, если включено `Автообновление подписки` (Subscription auto update) (по умолчанию выключено) | URL вашего провайдера | Правило `Использовать прокси` |
| Удалённый профиль маршрутизации | Когда вы добавляете или обновляете такой профиль, а также по расписанию, если включено `Автообновление профилей маршрутизации` (Routing profiles auto update) (по умолчанию выключено) | URL профиля. Адреса на `raw.githubusercontent.com` идут через `Зеркало наборов правил` (Remote Rule-set Mirror). | Правило `Использовать прокси` |
| Список профилей маршрутизации | Когда вы выбираете `Маршрутизация` (Routing) → `Скачать профили` (Download Profiles) → страну | Репозиторий throneproj/routeprofiles на GitHub, через зеркало | Правило `Использовать прокси` |
| Наборы правил | Когда запускается профиль, а для маршрутизации нужен набор правил (или `Включить AdBlock` (Enable AdBlock)), которого ещё нет в `cache.db`; примерно раз в день, пока работает профиль; а также когда вы выбираете `Маршрутизация` → `Обновить наборы правил` (Update Rule-Sets) | GitHub через `Зеркало наборов правил` (по умолчанию `jsDelivr (Cloudflare)`) или добавленный вами URL `.srs` | Отправляет ядро через outbound по умолчанию вашего профиля маршрутизации (напрямую, если это `block`) |
| Определение страны выхода | После каждого запуска профиля, а также когда вы открываете вкладку `Статистика` (Runtime Stats), пока работает профиль. Начиная с 1.4.0 — только если включено `Определять страну выхода` (Look up exit country; по умолчанию включено). | `Сервис определения IP` (Lookup service). При значении `Автоматически` (Automatic; по умолчанию) — сначала `https://api.ip2location.io/`, затем `http://ip-api.com/json/`, `https://ipwho.is/`, `https://ipinfo.io/json` и `https://www.cloudflare.com/cdn-cgi/trace`, пока один из них не назовёт страну | Всегда через локальный порт прокси |
| Тест задержки (URL test) | Когда вы запускаете тест задержки или щёлкаете строку состояния, когда открываете вкладку `Статистика`, пока работает автовыбор, а также после обновления подписки, если в группе включён `Запускать тест задержки` (Run URL test) | `URL теста задержки` (Latency Test URL), по умолчанию `http://cp.cloudflare.com/` | Через каждый проверяемый профиль |
| Тест IP | Только когда вы выбираете `Определить выходной IP выбранных` (Resolve Selected Out IP) или `Определить выходной IP группы` (Resolve out IP for group) | `https://api.ip2location.io/` | Через каждый проверяемый профиль |
| Тест скорости | Только когда вы запускаете тест скорости | Список серверов Speedtest.net и ближайший сервер Speedtest. В режиме `Простое скачивание` (Simple Download) — `URL для простого теста скачивания` (Simple Download URL), по умолчанию `http://cachefly.cachefly.net/1mb.test`. | Через каждый проверяемый профиль |
| Проверка связи | Пока работает автовыбор, и только если вы задали `URL проверки Direct` (Direct Test URL) или `URL проверки связи` (Connectivity URL) (по умолчанию оба пусты) | Этот URL | Напрямую |
| Разрешение доменов | Только когда вы выбираете `Преобразовать домены группы в IP` (Resolve Domain for group) или `Преобразовать выбранный домен в IP` (Resolve Selected Domain) | DNS-запросы доменных имён ваших серверов к серверу `DNS для прямых запросов` (Direct DNS) из ваших [настроек DNS](@/guides/dns.ru.md#settings) (по умолчанию `localhost`, то есть системный резолвер) | Начиная с 1.4.0 их отправляет ядро напрямую, никогда через прокси. Раньше Throne обращался к системному DNS-резолверу. |
| Проверка обновлений | Только когда вы выбираете `Программа` (Program) → `Проверить наличие обновлений` (Check For Update) (до 1.4.0: `Утилиты` (Tools) → `Проверить наличие обновлений`). Скачивание начинается, только когда вы нажмёте `Обновить` (Update). В macOS, в пакетах с системной библиотекой Qt и в копиях, установленных скриптом для Linux, этот пункт меню недоступен. | `api.github.com`: список релизов и, начиная с 1.4.0, если есть более новая версия, её `CHANGELOG.md` для списка изменений в окне обновления. Скачивается файл релиза на GitHub. | Правило `Использовать прокси` |
| Регистрация WARP | Только когда вы создаёте конфигурацию или идентификационные данные WARP | `api.cloudflareclient.com` или заданные вами `Домены регистрации…` (Registration Domains…) | Правило `Использовать прокси` |
| Геофайлы Xray | Только когда конфигурации Xray нужны `geoip.dat` или `geosite.dat` и вы соглашаетесь их скачать, когда вы нажимаете `Загрузить` (Download) или когда их запрашивает клиент Throne API | `URL файла GeoIP` (GeoIP Asset URL) и `URL файла GeoSite` (GeoSite Asset URL) (по умолчанию GitHub) | Правило `Использовать прокси` |
| Сканирование IP | Только когда вы запускаете сканирование в `Утилиты` → `IP-сканер` (IP Scanner) (начиная с 1.4.0) | Сначала TCP-подключение к публичным DNS-серверам, например `1.1.1.1:443` и `8.8.8.8:443`, чтобы проверить сеть; затем адреса сканируемого списка IP | Напрямую, через ваш сетевой адаптер, даже когда включён режим TUN |
| Обновление списка IP | Когда вы обновляете список IP, источником которого служит URL или набор правил, а также по расписанию, если вы включили автоматическое обновление этого списка (по умолчанию выключено) (начиная с 1.4.0) | URL списка; встроенные списки берутся из наборов правил на GitHub через `Зеркало наборов правил` | Правило `Использовать прокси` |
| Веб-панель | `Утилиты` → `Открыть веб-панель` (Open Web dashboard), только если в вашей сборке нет встроенной панели. В официальных сборках она есть. | GitHub | Всегда через локальный порт прокси |
| Резервные копии WebDAV | Только когда вы нажимаете `Upload to WebDAV` или `Restore from WebDAV...`, восстанавливаете или удаляете копию в этом списке либо нажимаете `Test` в `WebDAV Settings...` (начиная с 1.4.0). Автоматической загрузки нет. | Указанный вами `Server URL`, папка `Folder` (по умолчанию `Throne`). При загрузке отправляется файл резервной копии и обновляется список резервных копий `throne_backups.json` в этой папке. | Правило `Использовать прокси`. Если включено `Connect through the proxy` — всегда через локальный порт прокси. |
| NTP | Только если вы включили `Настройки NTP` (NTP Settings) | Указанный вами NTP-сервер | Выбранный вами `outbound`, по умолчанию `direct` |

В простом режиме `IP-сканер`, `Открыть веб-панель`, пункты меню для преобразования доменов и определения выходного IP, вкладка `Статистика` и `Настройки NTP` скрыты (см. [Простой и расширенный режим](@/get_started/configuration.ru.md#interface-mode)). Сделанные ранее настройки продолжают действовать, поэтому обновление списков IP по расписанию и NTP продолжают работать.

Об определении страны выхода:

- Throne использует его, чтобы показывать страну и город вашего подключения в строке состояния, в заголовке окна и на вкладке `Статистика`.
- Этот запрос всегда идёт через локальный порт прокси. Со встроенным профилем маршрутизации `Default` он выходит через ваш прокси, поэтому сервис определения видит адрес вашего прокси, а не ваш собственный.
- Начиная с 1.4.0 параметр `Настройки` → `Основные настройки` → `Общие` → `Определять страну выхода` отключает его, а `Сервис определения IP` выбирает сервис. См. [Тест IP и страны](@/guides/testing.ru.md#ip-test).
- К ip-api.com запрос идёт по обычному HTTP, к остальным сервисам — по HTTPS. Throne отправляет свой User-Agent.
- После запуска Throne пропускает этот запрос, если запущенный профиль выходит в сеть через профиль OpenVPN или OpenConnect.

О резервных копиях WebDAV:

- Резервная копия не шифруется. Она содержит части, отмеченные в разделе `Создать резервную копию` (Create Backup), например пароли ваших серверов и ссылки на подписки. Список резервных копий также хранит имя устройства (имя вашего компьютера, если вы не задали другое), случайный идентификатор устройства, платформу и версию Throne.
- `Username` и `Password` передаются серверу через базовую аутентификацию HTTP (basic authentication), которую `http://` не шифрует. Throne хранит их в своих настройках на этом компьютере и никогда не включает в резервную копию.
- См. [Резервные копии на WebDAV](@/guides/backup.ru.md#webdav).

Начиная с 1.3.2 проверка и скачивание обновлений всегда проверяют TLS-сертификат GitHub, даже если включён параметр `Основные настройки` → `Прочее` → `Игнорировать ошибки TLS` (Ignore TLS errors), потому что у файлов релиза нет другой подписи.

Запросы от клиента [Throne API](@/advanced/api.ru.md), например обновление подписок, импорт по URL и загрузка геофайлов, — это те же запросы, что и выше, и они идут по тем же маршрутам. Это относится и к веб-интерфейсу `thronectl` (`thronectl web`): его шлюз (gateway) обращается только к Throne API, а его страница ничего не загружает с других сайтов. [Headless Throne](@/headless/_index.ru.md) не определяет страну выхода и скачивает отсутствующие геофайлы Xray без вопросов.

DNS-запросы для трафика ваших приложений отправляются на серверы, указанные в `Настройки маршрутизации` (Routing Settings) → `DNS`, а начиная с 1.4.0 — на серверы активного профиля маршрутизации, если у него свои настройки DNS (см. [DNS для профиля маршрутизации](@/guides/dns.ru.md#route-dns)). См. [DNS](@/guides/dns.ru.md).

**Android:** Throne для Android выполняет такие же запросы для подписок, профилей маршрутизации, наборов правил, тестов и регистрации WARP. Резервные копии WebDAV отправляются только на сервер из `Настройки WebDAV` (WebDAV settings) и только когда вы создаёте или восстанавливаете копию либо проверяете соединение; после 2.0.3 — также когда вы удаляете копию. Эти запросы никогда не идут через локальный прокси. После 2.0.3 при загрузке, как и на компьютере, в список резервных копий также записываются имя устройства, случайный идентификатор устройства, платформа и версия. Если включён параметр `Настройки` → `Подписки` → `Использовать прокси` (Use proxy) или выбран режим `Только прокси` (Proxy only), собственные запросы приложения идут через локальный прокси, пока работает профиль. Пока ни один профиль не запущен, обновление подписок и регистрация WARP завершаются ошибкой «Запрос с прокси, но профиль не запущен.» (Request with proxy but no profile started.), если включён `Использовать прокси`, а в 2.0.3 и старее — также в режиме `Только прокси`; после 2.0.3 в одном только режиме `Только прокси` эти запросы идут напрямую. Проверка обновлений, загрузка профилей маршрутизации и списка наборов правил работают и без профиля: эти запросы идут напрямую. Начиная с 2.0.2 Throne для Android также определяет местоположение выхода после каждого подключения и после проверки подключения из нижней панели; запрос идёт через локальный прокси или через VPN, если смешанный вход (mixed) отключён. В 2.0.2 он всегда обращается к `http://ip-api.com/json/`. Начиная с 2.0.3 параметр `Настройки` → `Тестирование` (Testing) → `Look up exit country` отключает определение, а `Lookup service` предлагает те же сервисы, что и на компьютере. `Automatic` в 2.0.3 сначала обращается к ip-api.com, а после 2.0.3 — к IP2Location.io. Также начиная с 2.0.2, когда запускается или проверяется конфигурация Xray с правилами `geoip:` или `geosite:`, приложение скачивает `geoip.dat` и `geosite.dat` с GitHub (по умолчанию Loyalsoldier). Приложение проверяет наличие обновлений на GitHub, только когда вы нажимаете `Проверить обновления` (Check for updates), или раз в день, если включить `Проверять обновления ежедневно` (Check for updates daily) (по умолчанию выключено). После 2.0.3 экран обновления также скачивает с `api.github.com` список изменений новой версии. `Обновить список репозиториев` (Refresh repository list) на экране `Маршруты` (Routing) загружает с GitHub список профилей маршрутизации.

## Локальный порт прокси {#local-proxy}

Пока работает профиль, Throne слушает локальный порт прокси, который принимает подключения SOCKS5 и HTTP. По умолчанию это `127.0.0.1:2080`. К адресу `127.0.0.1` могут обращаться только программы на вашем компьютере, но любая из них может пользоваться этим портом без пароля.

Параметры находятся в `Настройки` → `Основные настройки` → `Общие` (Common) → `Настройки inbound` (Inbound Settings):

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| `Прослушиваемый адрес` (Listen Address) | `127.0.0.1` | `::` или `0.0.0.0` открывает порт для других устройств. |
| `Прослушиваемый порт` (Listen Port) | `2080` | Номер порта. |
| `Случайный порт` (Random port) | Выкл. | При каждом запуске использует свободный случайный порт. |
| `Включить авторизацию` (Enable Authorization) | Выкл. | Требует `Имя пользователя для inbound` (Inbound Username) и `Пароль для inbound` (Inbound Password). |
| `Отключить mixed inbound` (Disable Mixed Inbound) | Выкл. | Отключает порт. `Системный прокси` тогда использовать нельзя. |

`Разрешить подключаться другим устройствам` (Allow other devices to connect) в меню `Программа` (Program) и в меню трея устанавливает для `Прослушиваемый адрес` значение `::`. После этого вашим прокси может пользоваться любое устройство, которое может связаться с вашим компьютером. В этом случае установите флажок `Включить авторизацию`. См. [Доступ из локальной сети](@/guides/proxy_modes.ru.md#lan-sharing).

Другие локальные порты:

| Порт | По умолчанию | Кто может к нему обратиться |
| --- | --- | --- |
| `Порт DNS-сервера` (DNS Server Port) (`Основные настройки` → `Прочее`) | `5533` | Только этот компьютер (`127.0.0.1`). |
| Clash API (`Основные настройки` → `Ядро` (Core)) | Выкл. (пустой `Прослушиваемый порт`) | `Прослушиваемый адрес` Clash API, по умолчанию `127.0.0.1`. Задайте `Secret`, когда включаете его. |
| API sing-box / веб-панель (`Основные настройки` → `Ядро`) | Выкл. (пустой `Прослушиваемый порт`) | Только этот компьютер. Его защищает случайный `Secret`. |
| Throne API (`Настройки интеграции` (Integration Settings) → `Throne API`, начиная с 1.4.0) | Выкл.; порт `9095`, когда включён | Только этот компьютер (`127.0.0.1`) или, если для `Прослушивать` (Listen on) выбрано `Локальная сеть` (Local network), любое устройство, которое может связаться с вашим компьютером, в пределах `Разрешенные адреса` (Allowed addresses). Каждому клиенту нужен ключ. См. [Throne API и thronectl](@/advanced/api.ru.md#security). |

В простом режиме из параметров inbound выше виден только `Прослушиваемый порт` (Listen Port). Остальные параметры inbound, `Порт DNS-сервера`, вкладка `Ядро` (Core) и `Настройки интеграции` (Integration Settings) доступны только в расширенном режиме (см. [Простой и расширенный режим](@/get_started/configuration.ru.md#interface-mode)).

Когда профиль использует Xray, ядро также открывает внутренние порты на `127.0.0.1`, каждый из которых защищён случайным паролем. Throne и его ядро общаются друг с другом через локальный сокет, а не через сетевой порт.

[Headless Throne](@/headless/_index.ru.md) включает Throne API при первом запуске на `127.0.0.1:9095` с ключом в файле, который может читать только его пользователь.

Веб-интерфейс `thronectl` (`thronectl web`) — отдельная программа со своим портом, по умолчанию `127.0.0.1:9096`, и он требует пароль. См. [Веб-интерфейс](@/headless/web.ru.md#security).

**Android:** в `Настройки` (Settings) → `Входящие` (Inbound) есть аналогичные параметры: `Порт прокси SOCKS5` (Proxy port), `Разрешить подключения из локальной сети` (Allow connections from the LAN) (по умолчанию выключено) и `Включить авторизацию` (Enable authorization). Начиная с 2.0.2 API sing-box в `Настройки` → `Ядро` (Core) по умолчанию включён на `127.0.0.1:9091` со случайным секретом; он обслуживает `Панель sing-box` (sing-box dashboard) в боковом меню из файлов внутри приложения. В Throne для Android нет Throne API.

## Этот сайт {#website}

Этот сайт документации подсчитывает посещения с помощью Яндекс Метрики. Счётчик записывает просмотры страниц, страницу, с которой пришёл посетитель, щелчки по странице и по ссылкам, а также время пребывания на сайте. Запись сеансов отключена. В приложения Throne этот счётчик не входит.
