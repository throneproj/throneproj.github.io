این صفحه گزینه‌های خط فرمان Throne دسکتاپ، محل ذخیرهٔ داده‌های شما، کاربرد هر فایل، محل یافتن گزارش‌ها و روش شروع دوباره با تنظیمات پیش‌فرض را توضیح می‌دهد.

## خط فرمان {#command-line}

Throne این گزینه‌ها را می‌پذیرد:

| گزینه | کاری که انجام می‌دهد |
| --- | --- |
| `-appdata` | داده‌ها را به‌جای کنار برنامه، در پوشهٔ کاربری شما نگه می‌دارد. [پوشهٔ داده‌ها](#data-folder) را ببینید. |
| `-appdata <folder>` | داده‌ها را در `<folder>` نگه می‌دارد. Throne درون آن یک پوشهٔ `config` می‌سازد. |
| `-tray` | با پنجرهٔ پنهان اجرا می‌شود. فقط آیکون سینی سیستم نمایش داده می‌شود. |
| یک لینک `throne://` | لینک را طوری پردازش می‌کند که انگار روی آن کلیک کرده‌اید. [لینک‌های عمیق](@/advanced/deeplinks.fa.md) را ببینید. |
| مسیر فایل‌ها یا نشانی‌های `file://` | فایل‌ها را وارد می‌کند، مانند `برنامه` (Program) ← `Add profile from File(s)`. |

نمونه‌ها:

```bash
/opt/Throne/Throne -appdata
./Throne -appdata "$HOME/throne-test"
./Throne -tray
```

```powershell
.\Throne.exe -appdata D:\ThroneData
```

- Throne کلمهٔ بعد از `-appdata` را به‌عنوان پوشه در نظر می‌گیرد، مگر اینکه با `-` شروع شود.
- برای هر پوشهٔ داده فقط یک Throne اجرا می‌شود. اگر Throne از قبل در حال اجرا باشد، اجرای جدید لینک یا فایل‌هایش را به Throne در حال اجرا می‌سپارد، پنجرهٔ آن را به جلو می‌آورد و خارج می‌شود.
- **macOS:** برای ارسال گزینه‌ها، برنامهٔ درون بستهٔ برنامه (app bundle) را اجرا کنید؛ برای مثال `/Applications/Throne.app/Contents/MacOS/Throne -tray`. لینک‌هایی را که روی آن‌ها کلیک می‌کنید، خود macOS به Throne در حال اجرا می‌سپارد.

## پوشهٔ داده‌ها {#data-folder}

Throne داده‌های شما را در پوشه‌ای به نام `config` نگه می‌دارد. برای باز کردن آن، `تنظیمات` (Settings) ← `پوشه Config باز شود` (Open Config Folder) را انتخاب کنید.

Throne در یکی از دو حالت کار می‌کند:

- **حالت قابل‌حمل (portable):** پوشهٔ `config` درون پوشهٔ برنامهٔ Throne است.
- **حالت appdata:** پوشهٔ `config` در پوشهٔ کاربری شما است. Throne وقتی با `-appdata` اجرا شود، همیشه در macOS، و وقتی نتواند در پوشهٔ خودش بنویسد، از این حالت استفاده می‌کند.

در حالت appdata، پوشه این است:

| سیستم‌عامل | پوشهٔ داده‌ها |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Throne\config`، برای مثال `C:\Users\<you>\AppData\Local\Throne\config` |
| Linux | `~/.config/Throne/config`، یا اگر `XDG_CONFIG_HOME` را تنظیم کرده باشید، `$XDG_CONFIG_HOME/Throne/config` |
| macOS | `~/Library/Preferences/Throne/config` |

اینکه نسخهٔ شما از کدام حالت استفاده کند، به روش نصب آن بستگی دارد:

| روش نصب Throne | حالت | پوشهٔ داده‌ها |
| --- | --- | --- |
| فایل ZIP برای Windows | قابل‌حمل | `config` در پوشهٔ `Throne` استخراج‌شده |
| نصب‌کنندهٔ Windows، برای کاربر فعلی (پیش‌فرض) | قابل‌حمل | `config` در پوشهٔ نصب، که به‌طور پیش‌فرض `%LOCALAPPDATA%\Throne\config` است |
| نصب‌کنندهٔ Windows، برای همهٔ کاربران | Appdata (خودکار) | `%LOCALAPPDATA%\Throne\config` هر کاربر |
| فایل ZIP برای Linux | قابل‌حمل | `config` در پوشهٔ `Throne` استخراج‌شده |
| بستهٔ `.deb` یا `.rpm` یا اسکریپت نصب Linux | Appdata | `~/.config/Throne/config` |
| macOS | Appdata | `~/Library/Preferences/Throne/config` |

- میانبری که بسته‌های `.deb` و `.rpm` و اسکریپت نصب Linux در منوی برنامه‌ها می‌سازند، `/opt/Throne/Throne -appdata` را اجرا می‌کند.
- اگر Throne نتواند در پوشهٔ خودش بنویسد، برای مثال در `Program Files`، خودبه‌خود به حالت appdata می‌رود. بار اول، پوشهٔ `config` موجود شما را به آنجا کپی می‌کند. پس از آن، حتی اگر آن را با دسترسی مدیر (administrator) اجرا کنید، همچنان از پوشهٔ مخصوص کاربر استفاده می‌کند.
- بسته‌هایی از منابع دیگر (WinGet، Scoop، AUR، Nix) ممکن است از پوشه‌های دیگری استفاده کنند. `پوشه Config باز شود` همیشه پوشهٔ درست را نشان می‌دهد.

چند فایل کنار پوشهٔ `config` ذخیره می‌شوند، نه درون آن: فایل‌های geo مربوط به Xray یعنی `geoip.dat` و `geosite.dat`، و پوشهٔ `diagnostics` با فایل‌های `تنظیمات پایه` (Basic Settings) ← `Diagnostics`. در حالت قابل‌حمل، این محل پوشهٔ برنامهٔ Throne است. در حالت appdata، این محل پوشهٔ مخصوص کاربر است، برای مثال `%LOCALAPPDATA%\Throne`، حتی اگر با `-appdata` پوشهٔ دیگری تعیین کنید.

### فایل‌های پوشهٔ config {#config-files}

| فایل یا پوشه | محتوا |
| --- | --- |
| `throne.db` | نمایه‌ها، گروه‌ها، نمایه‌های مسیریابی، نمایه‌های OTP و تنظیمات شما، در یک پایگاه‌دادهٔ SQLite. تا وقتی Throne در حال اجراست، `throne.db-wal` و `throne.db-shm` کنار آن ظاهر می‌شوند. |
| `throne_stats.db` | تاریخچهٔ ترافیک برای `Tools` → `Traffic Stats`: داده‌های دقیقه‌به‌دقیقه برای 48 ساعت گذشته و داده‌های ساعتی برای 90 روز. `تنظیمات پایه` ← `استایل` (Style) ← `Disable Traffic Aggregation` این کار را متوقف می‌کند. |
| `cache.db` | حافظهٔ نهان (cache) هسته: مجموعه‌قوانینِ دانلودشده، آخرین انتخاب یک انتخابگر خودکار و، اگر `Save Cache To File` روشن باشد، حافظهٔ نهان DNS. |
| `logs/` | فایل‌های گزارش. [گزارش‌ها](#logs) را ببینید. |
| `crashes/` | فایل‌های crash dump (فقط Windows). 5 مورد جدیدتر نگه داشته می‌شوند. |
| `icons/` | آیکون‌های سفارشی سینی سیستم از `تنظیمات پایه` ← `استایل` ← `Enable Custom Icons`. |
| `dashboard/` | فایل‌های یک داشبورد وب برای Clash API. Throne این پوشه را با یک صفحهٔ موقت می‌سازد؛ آن را با فایل‌های داشبورد جایگزین کنید. |
| `sb-dashboard/` | داشبورد وبی که `Tools` → `Open Web dashboard` باز می‌کند. |

برای انتقال داده‌هایتان به رایانهٔ دیگر یا به Android، به‌جای کپی کردن فایل‌ها یک پشتیبان `.thrbackup` بسازید. [پشتیبان‌گیری و بازیابی](@/guides/backup.fa.md#backup-restore) را ببینید.

## گزارش‌ها {#logs}

زبانهٔ `گزارش‌ها` (Logs) در پایین پنجرهٔ اصلی، پیام‌های Throne و هسته را نشان می‌دهد. برای کپی کردن متن یا پاک کردن گزارش‌ها با `پاک کردن` (Clear)، روی متن گزارش‌ها راست‌کلیک کنید.

تنظیمات گزارش در `تنظیمات` ← `تنظیمات پایه` ← `Logging` قرار دارند:

| تنظیم | پیش‌فرض | کاری که انجام می‌دهد |
| --- | --- | --- |
| `حداکثر خطوط فایل لاگ` (Max log lines) | `200` | تعداد خطوطی که زبانهٔ `گزارش‌ها` نگه می‌دارد. |
| `پیمایش خودکار لاگ` (Auto-scroll log) | روشن | جدیدترین خط را در دید نگه می‌دارد. |
| `Sing-box Log level` | `info` | میزان جزئیاتی که هسته می‌نویسد: `trace`، `debug`، `info`، `warn`، `error`، `fatal` یا `panic`. |
| `Xray Log level` | `warning` | میزان جزئیاتی که Xray می‌نویسد: `debug`، `info`، `warning`، `error` یا `none`. |
| `Log Filtering` | خاموش | `Enable Include Rules` فقط خطوطی را نشان می‌دهد که با کلیدواژه‌ها یا عبارت‌های باقاعدهٔ (regular expression) شما منطبق‌اند. `Enable Exclude Rules` خطوط منطبق را پنهان می‌کند. فیلترها فقط زبانهٔ `گزارش‌ها` را تغییر می‌دهند، نه فایل گزارش را. |

برای گزارش باگ، `Sing-box Log level` را روی `debug` بگذارید، نمایه را دوباره اجرا کنید و مشکل را بازتولید کنید. سپس مراحل [گزارش باگ](@/help/bug_reports.fa.md#logs) را دنبال کنید.

### فایل گزارش {#log-file}

Throne گزارش‌ها را در فایل `logs/throne.log` درون پوشهٔ config هم می‌نویسد.

- این فایل با نسخهٔ Throne، سیستم‌عامل شما، گزینه‌های خط فرمان و پوشهٔ گزارش‌ها شروع می‌شود.
- این فایل همهٔ محتوای زبانهٔ `گزارش‌ها` و جزئیات بیشتری از خود Throne را در بر دارد.
- Throne در هر بار اجرا یک فایل جدید شروع می‌کند. وقتی حجم فایل به 4 MB برسد، Throne نام آن را به `throne.log.1` تغییر می‌دهد و فایل جدیدی شروع می‌کند. حداکثر سه بخش قدیمی، از `throne.log.1` تا `throne.log.3`، نگه داشته می‌شوند.
- اگر Throne به‌درستی بسته نشده باشد، گزارش آن نشست را با نام `crashed-YYYYMMDD-HHMMSS.log` در همان پوشه نگه می‌دارد. 5 مورد جدیدتر نگه داشته می‌شوند. در اجرای بعدی، زبانهٔ `گزارش‌ها` پیام «[Warn] Throne did not shut down cleanly last time. Diagnostics were saved to: …» (Throne دفعهٔ قبل به‌درستی بسته نشد. اطلاعات عیب‌یابی در این مسیر ذخیره شد: …) را نشان می‌دهد که در ادامهٔ آن، مسیر پوشهٔ گزارش‌ها می‌آید.

{% alert_warning() %}
گزارش‌ها ممکن است دامنه‌هایی را که بازدید کرده‌اید و نشانی سرورهای شما را در بر داشته باشند. پیش از انتشار عمومی یک فایل گزارش، آن را بررسی کنید.
{% end %}

**Android:** منوی کناری را باز کنید و روی `آمار و اطلاعات` (Logs) بزنید. `Share logs` و `Save logs…` از گزارش‌ها خروجی می‌گیرند. `Hide sensitive data` به‌طور پیش‌فرض روشن است. این گزینه در خروجی، گذرواژه‌ها، کلیدها، UUIDها، نام سرورها، نشانی‌های IP عمومی، نام شبکه‌های Wi-Fi و مسیر نشانی‌های URL را پنهان می‌کند. سطح گزارش در `تنظیمات` ← `Core` ← `سطح ثبت آمار` (Log level) است (پیش‌فرض: `warn`). [عیب‌یابی Android](@/android/troubleshooting.fa.md#logs) را ببینید.

## بازنشانی Throne {#reset}

Throne دکمهٔ بازنشانی ندارد. برای شروع دوباره با تنظیمات پیش‌فرض، یک پوشهٔ config جدید و خالی به Throne بدهید:

1. اگر می‌خواهید چیزی را نگه دارید، ابتدا یک پشتیبان بسازید: `تنظیمات` ← `تنظیمات پایه` ← `Backup and Restore` → `Create Backup...`.
2. برای دیدن محل پوشه، `تنظیمات` ← `پوشه Config باز شود` را انتخاب کنید.
3. با `خروج` (Exit) در منوی سینی سیستم یا منوی `برنامه` از Throne خارج شوید. بستن پنجره کافی نیست.
4. نام پوشهٔ `config` را تغییر دهید، برای مثال به `config-old`.
5. Throne را اجرا کنید. برنامه یک پوشهٔ `config` جدید با تنظیمات پیش‌فرض می‌سازد.

برای برگرداندن بخشی از داده‌های قدیمی‌تان، از `Restore from Backup...` در همان زبانه استفاده کنید و فقط بخش‌هایی را که لازم دارید انتخاب کنید. [پشتیبان‌گیری و بازیابی](@/guides/backup.fa.md#backup-restore) را ببینید.

برای لغو بازنشانی، از Throne خارج شوید، پوشهٔ `config` جدید را حذف کنید و نام `config-old` را دوباره به `config` برگردانید.

بازنشانی چیزهایی را که بیرون از پوشهٔ config ذخیره شده‌اند تغییر نمی‌دهد: `با سیستم شروع شود` (Start with system) (که یک مورد اجرای خودکار در سیستم‌عامل است)، ثبت لینک‌های `throne://` و فایل‌های geo مربوط به Xray.

**Windows:** اگر Throne را با نصب‌کننده نصب کرده باشید، هنگام حذف برنامه این پرسش نمایش داده می‌شود: «Also delete your Throne profiles, settings and logs?» (نمایه‌ها، تنظیمات و گزارش‌های Throne هم حذف شوند؟). برای حذف پوشهٔ config هم، `Yes` را انتخاب کنید.

**Android:** `تنظیمات` ← `بازگردانی تنظیمات پیش‌فرض` (Restore default settings) همهٔ تنظیمات را بازنشانی می‌کند، اما نمایه‌ها، گروه‌ها و نمایه‌های مسیریابی شما را نگه می‌دارد. سپس برنامه دوباره راه‌اندازی می‌شود. برای حذف همه‌چیز، داده‌های برنامه را در تنظیمات برنامه‌های Android پاک کنید. Throne برای Android داده‌هایش را در فضای ذخیره‌سازی خصوصی برنامه نگه می‌دارد که مدیرهای فایل نمی‌توانند آن را باز کنند؛ پس برای بیرون آوردن داده‌هایتان از یک پشتیبان `.thrbackup` استفاده کنید.
