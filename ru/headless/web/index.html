Веб-интерфейс

Управление Throne из браузера с помощью thronectl web: настройка, доступ с другого устройства и безопасность.

thronectl web предоставляет веб-интерфейс для headless Throne и для Throne для компьютера, в котором включён Throne API. Это небольшой веб-сервер, шлюз, входящий в thronectl: он обращается к Throne через API с тем же адресом и ключом, что и остальные команды thronectl.

Быстрый старт

Запускайте шлюз на том же устройстве, что и Throne: там Throne отвечает на все его запросы, включая административные.

Docker

Образ Docker запускает шлюз в том же контейнере, если задана переменная THRONE_WEB_LISTEN. В compose.yaml добавьте в службу throne:

services:
  throne:
    environment:
      THRONE_WEB_LISTEN: "*:9096"
    ports: ["2080:2080", "9096:9096"]

На хосте, доступном из интернета, публикуйте только адрес в локальной сети, например "192.168.1.2:9096:9096". С docker run добавьте -e THRONE_WEB_LISTEN='*:9096' -p 9096:9096.

docker compose up -d
docker compose logs throne

В логе будут пароль и отпечаток сертификата. Откройте https://<host>:9096/, проверьте отпечаток и войдите.

Шлюз хранит своё состояние в /var/lib/throne/web на томе с данными. Он перезапускается через 3 секунды после завершения, поэтому неверный параметр THRONE_WEB_* повторяется в логе.

Пакеты для Linux (systemd)

Пакеты .deb и .rpm устанавливают throne-web.service, который запускает thronectl web рядом с throne.service от собственного динамического пользователя, с ключом Throne в качестве учётных данных (credential) и с состоянием в /var/lib/throne-web:

sudo systemctl enable --now throne-web
sudo journalctl -u throne-web | grep 'web UI password'

Он слушает 127.0.0.1:9096: открывайте его через туннель SSH. Чтобы изменить его параметры, раскомментируйте их в /etc/throne/web.env и выполните sudo systemctl restart throne-web; обновления сохраняют ваши правки. Никогда не записывайте в этот файл ключ или пароль.

  • Пользователь юнита не может читать файлы, доступные только root, например ключ TLS или файл пароля. Передайте их через LoadCredential= (sudo systemctl edit throne-web), как показано в /etc/throne/web.env.
  • Для порта ниже 1024 нужна возможность CAP_NET_BIND_SERVICE в AmbientCapabilities= и CapabilityBoundingSet=.

Вручную, в любой системе

На устройстве с Throne подключите thronectl к Throne и запустите шлюз:

export THRONE_KEY_FILE=~/.config/throne/api-key
thronectl web

Он один раз выводит пароль и работает на http://127.0.0.1:9096/, пока вы не нажмёте Ctrl+C. Для Throne для компьютера сначала включите API и подключите thronectl.

Доступ с другого устройства

Шлюз слушает 127.0.0.1:9096, куда можно обратиться только с устройства с Throne.

Туннель SSH

ssh -L 9096:127.0.0.1:9096 user@host

Пока сеанс открыт, откройте http://localhost:9096/ на своём компьютере (https:// для Docker). Если порт 9096 там занят, используйте другой локальный порт, например -L 19096:127.0.0.1:9096.

Локальная сеть (HTTPS)

thronectl web --listen '*:9096'

*:9096 слушает все адреса устройства, 192.168.1.2:9096 — один. На сетевом адресе шлюз работает по HTTPS. Если вы не дадите ему сертификат, он создаёт самоподписанный и при каждом запуске выводит его отпечаток SHA-256; его показывает и страница System. Браузер предупредит, что сертификату нельзя доверять: откройте сведения о сертификате и принимайте его, только если его отпечаток SHA-256 совпадает с выведенным. Если они различаются, что-то между вами и устройством перехватывает соединение: не входите.

Разрешите порт 9096 в брандмауэре устройства, и только из вашей сети.

  • Сертификат выписан на localhost, имя хоста и адреса, которые были у устройства в тот момент, и действует 10 лет. Чтобы получить новый, например после смены адреса, удалите папку tls в каталоге состояния и перезапустите шлюз.
  • Чтобы использовать собственный сертификат, передайте цепочку сертификатов и закрытый ключ в файлах PEM через --tls-cert и --tls-key. После продления перезапустите шлюз.

За обратным прокси

Оставьте шлюз на loopback и передайте ему своё имя хоста:

thronectl web --allow-host throne.example.com

Если прокси работает на другом устройстве или в другом контейнере, шлюз должен слушать сетевой адрес с --tls off. Сделайте его доступным только прокси: пароль передаётся по нему без шифрования. Прокси должен:

  • Передавать заголовок Host без изменений, иначе изменения отклоняются с 403 csrf. nginx заменяет этот заголовок, если его не задать; Caddy сохраняет его.
  • Принимать тела запросов до 512 MiB — это самая большая резервная копия, которую восстанавливает веб-интерфейс. nginx принимает 1 MiB, если не задать client_max_body_size.
  • Не буферизовать ответы: обновления и лог приходят потоком. Заголовок шлюза X-Accel-Buffering: no отключает буферизацию в nginx.

nginx:

server {
    listen 443 ssl;
    server_name throne.example.com;
    ssl_certificate     /etc/ssl/certs/throne.example.com.pem;
    ssl_certificate_key /etc/ssl/private/throne.example.com.key;

    location / {
        proxy_pass http://127.0.0.1:9096;
        proxy_set_header Host $http_host;
        client_max_body_size 512m;
    }
}

Caddy:

throne.example.com {
    reverse_proxy 127.0.0.1:9096
}

За прокси все браузеры приходят с адреса прокси, поэтому неудачные попытки входа из одного браузера блокируют и остальные.

Пароль

У веб-интерфейса один пароль и нет учётных записей пользователей. При первом запуске шлюз создаёт случайный пароль, сохраняет его хеш в файле password в своём каталоге состояния и один раз выводит пароль: см. docker compose logs throne, sudo journalctl -u throne-web | grep 'web UI password' или терминал, где вы запустили thronectl web.

Эта строка остаётся в логе, который могут читать root, группы adm и systemd-journal и все, кому разрешено запускать docker. Смените пароль после первого входа: на странице System или командой thronectl web passwd, запущенной от имени пользователя шлюза с тем же каталогом состояния. Пароль должен содержать не меньше 8 символов, а его смена завершает все остальные сеансы.

docker compose exec throne thronectl web passwd              # Docker
sudo thronectl web passwd --state-dir /var/lib/throne-web    # юнит systemd

Забытый пароль. Задайте новый командой thronectl web passwd или удалите файл password и перезапустите шлюз — тогда он выведет новый.

Файл пароля. --password-file FILE (THRONE_WEB_PASSWORD_FILE) берёт пароль открытым текстом из файла вместо сохранённого хеша, например из секрета Docker в /run/secrets/. Шлюз перечитывает файл каждые 5 секунд и завершает все сеансы, когда он меняется. Чтобы сменить пароль, измените файл.

Сеансы. Вход действует, пока браузер не простаивает 12 часов, и не дольше 7 дней. Перезапуск шлюза завершает все сеансы. Он хранит не больше 64 сеансов; ещё один вход завершает сеанс, который дольше всех не использовался.

Что умеет веб-интерфейс

Страница Что можно делать
Status Состояние, запущенный профиль и скорость; подключение и отключение; TUN и системный прокси (только в Throne для компьютера); профиль маршрутизации; идущие тесты.
Profiles Просматривать, фильтровать, тестировать, подключать, редактировать и удалять профили или подключать лучший профиль группы. Импортировать ссылки для обмена, файл или URL. Добавлять, обновлять и удалять группы и подписки.
Routing Добавлять, редактировать и удалять профили маршрутизации. Включать и выключать WARP, выбирать его режим и регистрировать его (при этом принимаются условия WARP от Cloudflare).
Traffic Скорость и суммарный трафик по профилям или приложениям за 24 часа, 7 дней или 30 дней.
Connections Открытые и закрытые подключения с процессом, адресом назначения, исходящим подключением (outbound) и правилом; закрыть одно или все.
Logs Лог Throne по мере записи; страница хранит последние 5000 строк.
Settings Настройки, которыми управляет API, геофайлы и наборы правил запущенного профиля.
Backup Скачать резервную копию или загрузить её и восстановить выбранные части.
System Версии, есть ли у шлюза права администратора, отпечаток сертификата, пароль, выход, перезапуск Throne и завершение его работы.

Изменения, сделанные в окне Throne, через thronectl или при обновлении подписки, появляются в течение нескольких секунд.

Что остаётся в приложении для компьютера

Веб-интерфейс не редактирует:

  • записи OTP,
  • собственный профиль маршрутизации группы (для новой подписки его задаёт thronectl sub add),
  • конечные точки (endpoints) OpenVPN и OpenConnect в профиле маршрутизации,
  • профили дополнительного ядра (Extra Core) и профили с настройками, которые может задать только окно Throne, например со ссылкой на запись OTP,
  • настройки, которыми API не управляет.

Настройте это в Throne для компьютера и перенесите с помощью резервной копии, восстановив её на странице Backup или командой thronectl backup restore. Резервные копии с профилями дополнительного ядра отклоняются.

Параметры

Флаг важнее своей переменной.

Флаг Переменная Значение по умолчанию и смысл
--listen ADDR THRONE_WEB_LISTEN 127.0.0.1:9096. Принимает PORT (на 127.0.0.1), IP:PORT, [IPv6]:PORT и *:PORT (все адреса), но не имена хостов.
--state-dir DIR THRONE_WEB_STATE_DIR Хеш пароля и самоподписанный сертификат. По умолчанию: $STATE_DIRECTORY от systemd, иначе ~/.config/thronectl/web в Linux, ~/Library/Application Support/thronectl/web в macOS, %AppData%\thronectl\web в Windows.
--tls auto|on|off THRONE_WEB_TLS auto (по умолчанию): HTTPS на сетевом адресе, обычный HTTP на loopback. on: HTTPS и на loopback. off: обычный HTTP; на сетевом адресе — только за обратным прокси с TLS.
--tls-cert FILE, --tls-key FILE THRONE_WEB_TLS_CERT, THRONE_WEB_TLS_KEY Ваша цепочка сертификатов и закрытый ключ в PEM вместо самоподписанного сертификата. С auto они включают HTTPS и на loopback.
--allow-host LIST THRONE_WEB_ALLOW_HOST Дополнительные имена хостов, которыми могут пользоваться браузеры, например имя обратного прокси, через запятую или пробел. Для защиты от DNS rebinding шлюз отвечает на другие имена 421 Misdirected Request: на loopback он принимает только эти имена, localhost, 127.0.0.1 и ::1; на сетевом адресе — любое имя, если этот параметр не задан.
--password-file FILE THRONE_WEB_PASSWORD_FILE Пароль открытым текстом вместо сохранённого хеша. См. Пароль.

Шлюз находит Throne так же, как любая команда thronectl, а под systemd также читает ключ из учётных данных api.key. thronectl web завершается с кодом 0, если его остановили с помощью Ctrl+C или SIGTERM; с кодом 2 при неверном параметре или переменной, отсутствии ключа, плохом файле пароля или файле password либо сертификате, который не загружается; с кодом 3, если он не может начать слушать, или при другой ошибке.

Безопасность

  • Веб-интерфейс — административный клиент. Тот, кто вошёл, может делать то же, что и thronectl, в том числе скачивать резервные копии, которые содержат учётные данные ваших профилей и секреты OTP в открытом виде, и завершать работу Throne. Давайте пароль только тем, кому можно управлять Throne.
  • Ключ API остаётся у шлюза. Браузер получает только cookie сеанса и токен сеанса.
  • Ограничения входа. После 5 неудачных попыток входа за 5 минут с одного адреса (для IPv6 — из одной сети /64) шлюз отклоняет вход с этого адреса на 60 секунд, а после каждой следующей неудачи — вдвое дольше, но не больше 15 минут. Если всего за минуту не удаётся больше 30 попыток входа, он отклоняет любой вход, пока эта минута не пройдёт.
  • Предпочитайте loopback и туннель SSH. В сети используйте HTTPS и проверяйте отпечаток сертификата или используйте сертификат, которому доверяют браузеры. Обычный HTTP на сетевом адресе передаёт пароль и сеанс без шифрования.
  • Запускайте шлюз на устройстве с Throne, чтобы API Throne мог оставаться на loopback.

Устранение неполадок

Симптом Причина и решение
Throne is not reachable. Retrying… (throne_unreachable) Throne не запущен, его API выключен или у шлюза неверный адрес. Выполните thronectl status с настройками шлюза.
Throne refuses the web UI или Throne refused the connection (throne_rejected) У шлюза неверный ключ. Дайте ему текущий ключ Throne (config/api.key в каталоге данных) и перезапустите его. С другого устройства 5 неудачных попыток с его адреса, в том числе от другого клиента со старым ключом, блокируют его на 60 секунд.
The web UI's connection to Throne lacks admin rights (forbidden) Шлюз работает не на устройстве с Throne. Запустите его там или разрешите Throne отвечать на административные запросы из сети: --api-admin-lan для headless Throne, Разрешить управление из локальной сети (Allow management from the local network) в приложении для компьютера.
421 Misdirected Request: this host name is not accepted Откройте шлюз как localhost или по IP-адресу либо добавьте имя через --allow-host.
За обратным прокси не удаётся войти: The web UI server refused the request because it came from another origin (403 csrf) Прокси меняет заголовок Host: см. За обратным прокси.
Too many failed attempts. Try again in … s. (rate_limited) Подождите, пока закончится обратный отсчёт.
thronectl web завершается: address already in use; --listen picks another address Порт 9096 занят другой программой или другим thronectl web. Остановите её или укажите другой --listen.
Восстановление резервной копии через nginx завершается ошибкой 413 Задайте client_max_body_size 512m;.
The password comes from a password file Измените файл, указанный в --password-file.
