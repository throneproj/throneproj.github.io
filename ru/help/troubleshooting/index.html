Устранение неполадок

Решения проблем с режимом TUN, DNS, подписками, системным прокси, производительностью и запуском Throne для компьютера.

Найдите свою проблему и выполните проверки по порядку. Параметры, названные здесь, могут быть скрыты в простом режиме: нажмите Ctrl+K и введите название (Простой и расширенный режим). Для Android см. Устранение неполадок на Android. Если ничего не помогает, сообщите об ошибке.

Первые проверки

  1. Обновите Throne через Программа (Program) → Проверить наличие обновлений (Check For Update) или, если этот пункт неактивен, скачайте новую версию со страницы загрузок.
  2. Просмотрите вкладку Логи (Logs) внизу главного окна.
  3. Проверьте профиль с помощью Тест задержки (Url Test Selected) (Ctrl+Shift+S). Если тест не прошёл, сначала исправьте сервер или профиль.
  4. Если профиль работает с Системный прокси (System Proxy), но не работает с Режим TUN (Tun Mode), проблема в настройке TUN.

Режим TUN

TUN включён, но ничего не загружается

  1. Закройте другие VPN-приложения. Они могут перехватывать маршруты.
  2. Windows: разрешите ThroneCore.exe в брандмауэре Windows. Если вы отказали, когда Windows спросила, она продолжит блокировать ядро и больше не спросит (#1433).
  3. Windows: сетевая защита антивирусов, например Avast или ESET, может блокировать адаптер TUN без каких-либо сообщений (#1687, #1357). Добавьте папку Throne в исключения.
  4. Windows: для проверки выключите Строгая маршрутизация (Strict Route) в окне Настройки режима TUN (Tun Settings). Без него возможны утечки DNS; см. Защита от утечек DNS в Windows.
  5. Linux: отключите DNS over TLS для всей системы в systemd-resolved (#1146) и оставьте включённым Автоматическое перенаправление (Auto Redirect) в окне Настройки режима TUN.

TUN не запускается

  • Нет прав: примите запрос Throne на права администратора или root (FAQ). Если включён параметр Не запрашивать повышение прав (Disable Privilege request), права нужно выдать самостоятельно.
  • «Строгая маршрутизация недоступна» (Windows): выключите Строгая маршрутизация (Strict Route) в окне Настройки режима TUN (Tun Settings) и снова запустите профиль.
  • «Некорректное поведение устройства TUN»: нажмите Сбросить (Reset) в сообщении или Перезапустить ядро (Restart Core) в окне Настройки режима TUN и снова запустите профиль. Если не помогает, перезагрузите компьютер.
  • Запуск зависает (Windows): очистка кэша DNS может зависать из-за очень большого файла HOSTS (#1906). Держите его небольшим.
  • «Tun на этом компьютере занят фоновым Throne (PID …); остановите его или используйте thronectl.» См. Throne работает в фоновом режиме.

TUN мешает другим программам

Пока включён режим TUN, могут перестать работать мобильный хот-спот, виртуальные машины, Docker или рабочий VPN. См. Режим TUN и Рецепты.

DNS

Сайты не открываются, или в логе ошибки DNS

  1. В Настройки (Settings) → Настройки маршрутизации (Routing Settings) → DNS Удалённый DNS (Remote DNS) должен быть доступен через ваш прокси, а DNS для прямых запросов (Direct DNS) должен работать без него. Попробуйте один из предустановленных серверов.
  2. Если в вашей сети нет IPv6, не выбирайте ipv6_only в полях Стратегия разрешения доменов по умолчанию (Default Domain Strategy) и Стратегия разрешения доменов в запросах (Resolve Domain Strategy) на вкладке Основные (Common) (#1743). Оставьте их пустыми или используйте prefer_ipv4.

Тест на утечку показывает DNS моего интернет-провайдера

Обычно это ожидаемо; см. FAQ.

Подписки

Обновление завершается ошибкой

В логе появляется Ошибка запроса подписки …: … (Requesting subscription … error: …) с указанием причины.

  • «Запрос через прокси, но профиль не запущен.» Когда включён Использовать прокси (Use proxy) (Основные настройки (Basic Settings) → Прочее (Miscellaneous)) или Системный прокси (System Proxy), Throne отправляет собственные запросы через свой прокси. Сначала запустите профиль или выключите оба параметра. Если включён Отключить mixed inbound (Disable Mixed Inbound), выключите Использовать прокси (#1689).
  • Сайт провайдера заблокирован в вашей стране: запустите работающий профиль, включите Использовать прокси и обновите подписку снова.
  • Сервер отвечает 403 или не присылает ничего полезного: многие провайдеры отвечают только знакомым им приложениям. Укажите User Agent, который ожидает ваш провайдер: для всех групп — в Основные настройки (Basic Settings) → Подписка (Subscription), для одной группы — в Группы (Groups) → Редактировать текущую группу (Edit current Group) → Доп. настройки (Advanced). По умолчанию Throne отправляет Throne/<version>.
  • «Device fingerprint required» (требуется отпечаток устройства) или похожее сообщение: провайдеру нужен ваш HWID.

Обновление не находит профилей

В логе написано «В подписке не найдено профилей» (No profiles found in the subscription). Убедитесь, что ссылка — это URL подписки, а не веб-страница и не ссылка для приложения: ссылки happ://crypt и v2raytun://crypt зашифрованы для этих приложений, и Throne не может их прочитать. Попробуйте также другой User Agent.

Группа не обновляется

  • У профилей, добавленных через Добавить профили в эту группу (Add profiles to this group), нет URL подписки. Снова вставьте URL через Ctrl+V и выберите Создать новую группу подписки (Create new subscription group).
  • Для автоматических обновлений нужен параметр Основные настройки (Basic Settings) → Подписка (Subscription) → Автообновление подписки (Subscription auto update), который по умолчанию выключен; группы с отмеченным Не обновлять автоматически (Skip automatic update) пропускаются.

Профили изменились или пропали после обновления? См. FAQ и Подписки и группы.

Системный прокси

Некоторые приложения игнорируют системный прокси

Терминалы (например, PowerShell), приложения из Windows Store, Discord и звонки Telegram обычно его игнорируют (#370, #1631). Для таких приложений используйте Режим TUN (Tun Mode); см. Какой режим выбрать.

Системный прокси не устанавливается

  1. Запустите профиль. Throne устанавливает системный прокси только на то время, пока запущен профиль.
  2. «Cannot set system proxy when mixed inbound is disabled.» (нельзя установить системный прокси, когда смешанный входящий порт отключён) Выключите Отключить mixed inbound (Disable Mixed Inbound) в Основные настройки (Basic Settings) → Общие (Common).
  3. Linux: Throne устанавливает системный прокси только в GNOME и KDE. В других окружениях рабочего стола укажите в системных настройках адрес Mixed: … из строки состояния или используйте режим TUN. Не запускайте Throne от имени root (#864).

Нет интернета после закрытия Throne

Если Throne был принудительно закрыт, когда был включён Системный прокси (System Proxy), системный прокси всё ещё указывает на Throne. См. FAQ.

Производительность и сбои

Высокая нагрузка на процессор или память

  1. Держите в сумме меньше примерно 10 000 профилей. После теста задержки удалите нерабочие профили через Группы (Groups) → Очистка (Clean up) → Удалить недоступные (Remove Unavailable).
  2. Торрент-клиенты при включённом мультиплексировании (Multiplex) могут сильно нагружать процессор (#1090). По умолчанию мультиплексирование выключено; если вы его включили, выключите его в профиле или снимите флажок Вкл. по умолчанию (Default On) в Настройки (Settings) → Предустановленные настройки (Preset Settings) → Мультиплексирование (Multiplex).
  3. Снимите флажок Основные настройки (Basic Settings) → Интерфейс (Style) → Статистика подключений (Connection statistics) → Включить (Enable). Вкладка Подключения (Connections) тогда остаётся пустой.
  4. Windows: Вкл. TUN-маршрутизацию (Enable Tun Routing) с большими наборами правил может вызывать очень высокую нагрузку на процессор. Выключите этот параметр в окне Настройки режима TUN (Tun Settings).

Сбой Throne или ядра

  • «Ядро слишком часто останавливается, отмена автоматического перезапуска этого профиля». Ядро постоянно падает, поэтому Throne перестал перезапускать его с вашим профилем.
  • «В прошлый раз Throne не завершил работу корректно» при следующем запуске: произошёл сбой Throne. Лог этого сеанса сохраняется как logs/crashed-<date>-<time>.log в папке конфигурации; в Windows в папке crashes также сохраняется отчёт о сбое.
  • Чтобы исключить проблему в конфигурации, выйдите из Throne, переименуйте папку config и снова запустите Throne; см. Командная строка, файлы и логи.
  • Сообщите о сбое и приложите эти файлы: Как сообщить об ошибке.

Проблемы с запуском и рабочим окружением

Throne не запускается

  • «Incompatible processor. This Qt build requires the following features: sse4.2 popcnt» (несовместимый процессор): в Windows используйте windowslegacy64.zip, в Linux — пакет -system-qt (FAQ).

  • Linux: Could not load the Qt platform plugin "xcb": если Throne использует Qt вашей системы, установите libxcb-cursor0 (Debian, Ubuntu) или xcb-util-cursor (Fedora, RHEL) (#1096). Если ошибка появляется с ZIP-файлом или обычным пакетом, используйте пакет -system-qt; он помогает и при других ошибках Qt.

  • macOS: «Throne is damaged and can't be opened» (Throne повреждён, и его не удаётся открыть): Throne не подписан сертификатом Apple. Переместите Throne.app в /Applications, снимите флаг карантина в приложении Терминал (Terminal) и снова откройте Throne:

    xattr -d com.apple.quarantine /Applications/Throne.app

В Linux запустите Throne из терминала, чтобы увидеть ошибку: /opt/Throne/Throne -appdata для пакетов или ./Throne в папке копии из ZIP-архива. Не используйте sudo: права root нужны только ядру (FAQ).

Нет значка в трее в GNOME

Установите и включите расширение AppIndicator. Если окно скрыто, запустите Throne ещё раз, чтобы показать его, или включите Основные настройки (Basic Settings) → Интерфейс (Style) → Откл. сворачивание в трей (Disable tray), чтобы при закрытии окна Throne завершал работу.

Throne не подключается заново после перезапуска

Включите Программа (Program) → Запоминать последний профиль (Remember last profile). При следующем запуске Throne снова запустит профиль, который работал, когда вы выходили, и восстановит Системный прокси (System Proxy) и Режим TUN (Tun Mode) в том же состоянии. Программа → Запускать вместе с системой (Start with system) запускает Throne при входе в систему; в Windows этот пункт также получает права администратора без запроса, если Throne работает от имени администратора (FAQ).

Ссылки throne:// ничего не делают

В Windows и Linux копии из ZIP-архива по умолчанию не регистрируют ссылки throne://. Включите Основные настройки (Basic Settings) → Общие (Common) → Регистрировать обработчик ссылок throne:// при запуске (Register throne:// links at startup) или нажмите Установить (Install) рядом с этим параметром. Другие проверки: Глубокие ссылки.

Throne работает в фоновом режиме

Headless Throne, например служба systemd, может работать на том же компьютере, что и окно Throne:

  • «Throne работает в фоновом режиме (PID …). Остановите службу или используйте thronectl.» (Throne is running in the background (PID …). Stop the service or use thronectl.), и окно не открывается: headless Throne использует ту же папку данных. Остановите его (например, systemctl --user stop throne) и снова запустите Throne или управляйте им с помощью thronectl.
  • «На этом компьютере работает фоновый Throne (PID …, каталог данных: …)»: работает headless Throne с другой папкой данных. Окно Throne работает, но без режима TUN.
  • «Tun на этом компьютере занят фоновым Throne (PID …); остановите его или используйте thronectl.» Пока работает любой headless Throne, окно не может использовать режим TUN, даже если сам headless Throne TUN не использует. Остановите headless Throne.
  • «Обновление недоступно, пока из этой установки работает фоновый Throne (PID …); сначала остановите его.» Остановите его, обновите Throne и снова запустите headless Throne.
  • «Another Throne instance (PID …) is using this data directory» (этот каталог данных использует другой экземпляр Throne): папку данных занимает другой Throne, но он не отвечает. Завершите его или его процесс и снова запустите Throne.
