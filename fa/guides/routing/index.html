مسیریابی

تعیین کنید کدام ترافیک از پروکسی عبور کند، کدام مستقیم برود و کدام مسدود شود؛ با نمایه‌های آماده یا قوانین خودتان.

مسیریابی تعیین می‌کند هر اتصال به کجا برود: از طریق پروکسی شما، مستقیم به اینترنت، یا هیچ‌جا. این صفحه نشان می‌دهد چگونه یک نمایهٔ مسیریابی آماده برای کشورتان دانلود کنید، قوانین خودتان را بنویسید و نمایه‌ها را به اشتراک بگذارید. اگر می‌خواهید همه‌چیز از پروکسی عبور کند، لازم نیست چیزی را تغییر دهید.

مسیریابی چگونه کار می‌کند

نمایهٔ مسیریابی فهرستی از قوانین به‌همراه یک خروجی پیش‌فرض است. وقتی اتصالی آغاز می‌شود، Throne قوانین را از بالا به پایین بررسی می‌کند. نخستین قانونی که منطبق شود، تعیین می‌کند اتصال به کجا برود. اگر هیچ قانونی منطبق نشود، اتصال از خروجی پیش‌فرض استفاده می‌کند.

خروجی (outbound) جایی است که ترافیک می‌تواند به آن برود:

خروجی ترافیک به کجا می‌رود
proxy از طریق نمایه‌ای که آغاز کرده‌اید. وقتی WARP روشن است، WARP به‌عنوان آخرین هاپ (hop) اضافه می‌شود.
direct مستقیم به اینترنت، بدون پروکسی.
block هیچ‌جا. اتصال رد می‌شود.
warp-bypass از طریق نمایه‌ای که آغاز کرده‌اید، اما بدون WARP. وقتی WARP خاموش است، همانند proxy است. WARP را ببینید.
یک نمایهٔ ذخیره‌شده از طریق همان نمایه، به‌جای نمایه‌ای که آغاز کرده‌اید. فقط در قوانین پیشرفته.

در هر زمان دقیقاً یک نمایهٔ مسیریابی فعال است. نمایهٔ داخلی Default فقط یک قانون DNS (Route DNS) دارد و همه‌چیز را به proxy می‌فرستد.

برای تغییر نمایهٔ مسیریابی فعال، از یکی از این راه‌ها استفاده کنید:

  • فهرست پایین منوی مسیریابی (Routing). نمایهٔ فعال علامت تیک دارد.
  • منوی سینی سیستم (tray) ← Select Routing.
  • تنظیمات (Settings) ← تنظیمات مسیریابی (Routing Settings) ← متداول (Common) ← نمایه مسیریابی (Routing Profile)، سپس تایید (OK).

انتخاب یک نمایهٔ مسیریابی از منوی مسیریابی (Routing) یا از سینی سیستم، اتصال در حال اجرا را دوباره راه‌اندازی می‌کند تا قوانین جدید بی‌درنگ اعمال شوند. وقتی نمایهٔ مسیریابی فعال Default نباشد، نام آن در عنوان پنجره نمایش داده می‌شود.

دانلود نمایه‌های آماده

Throne می‌تواند نمایه‌های مسیریابی‌ای را دانلود کند که برای چین، ایران و روسیه نگهداری می‌شوند.

  1. منوی مسیریابی (Routing) ← Download Profiles را باز کنید و China، Iran یا Russia را انتخاب کنید.
  2. Throne نمایه‌هایی را که اضافه خواهد کرد فهرست می‌کند: «Add these remote routing profiles?» (این نمایه‌های مسیریابی راه‌دور اضافه شوند؟). تیک Auto update را نگه دارید و روی تایید (OK) کلیک کنید.
  3. دوباره منوی مسیریابی (Routing) را باز کنید و یکی از نمایه‌های جدید را در پایین آن انتخاب کنید. دانلود به‌تنهایی نمایهٔ فعال شما را تغییر نمی‌دهد.
کشور نمایه کارکرد
چین Bypass China همه‌چیز را از پروکسی عبور می‌دهد، به‌جز سایت‌های چینی، نشانی‌های IP چین و شبکهٔ محلی شما که مستقیم می‌روند. سایت‌های موجود در یک فهرست ضدسانسور همیشه از پروکسی استفاده می‌کنند.
چین Proxy China Blocked همه‌چیز را مستقیم می‌فرستد، به‌جز سایت‌هایی که مسدود بودنشان در چین شناخته‌شده است.
ایران Bypass Iran همه‌چیز را از پروکسی عبور می‌دهد، به‌جز سایت‌های ایرانی، نشانی‌های IP ایران و شبکهٔ محلی شما.
روسیه Bypass Russia همه‌چیز را از پروکسی عبور می‌دهد، به‌جز سایت‌ها و نشانی‌های IP روسیه، سایت‌هایی که فقط درون روسیه کار می‌کنند و شبکهٔ محلی شما.
روسیه Proxy Russia Blocked همه‌چیز را مستقیم می‌فرستد، به‌جز سایت‌ها و نشانی‌های IP مسدودشده در روسیه.
روسیه Proxy Antizapret همه‌چیز را مستقیم می‌فرستد، به‌جز سایت‌های موجود در فهرست مسدودی Antizapret.
روسیه Proxy Refilter همه‌چیز را مستقیم می‌فرستد، به‌جز سایت‌ها و نشانی‌های IP موجود در فهرست مسدودی Re:filter.

نمایهٔ «Bypass» زمانی برای شما مناسب است که بیشتر سایت‌هایی که بازدید می‌کنید خارجی باشند. نمایهٔ «Proxy … Blocked» ترافیک کمتری را از سرور شما عبور می‌دهد؛ این کار وقتی سرور کُند است یا محدودیت حجم دارد کمک می‌کند. عیب آن: سایت مسدودی که در فهرست نباشد، باز نمی‌شود.

این نمایه‌ها جایگزین یکدیگرند. نمایهٔ دلخواهتان را فعال کنید و بقیه را رها کنید؛ نیازی به حذف آن‌ها نیست. این‌ها نمایهٔ راه‌دور هستند، پس می‌توانند خودشان را به‌روز کنند. فهرست‌ها در مخزن throneproj/routeprofiles نگهداری می‌شوند و ممکن است به‌مرور تغییر کنند.

اگر دانلود با خطای «Requesting profile error» (خطا در درخواست نمایه) ناموفق شد، Remote Rule-set Mirror دیگری انتخاب کنید (پایین‌تر را ببینید) و دوباره امتحان کنید.

نمایه‌های مسیریابی

تنظیمات (Settings) ← تنظیمات مسیریابی (Routing Settings)، که نخستین گزینهٔ منوی مسیریابی (Routing) نیز هست، پنجرهٔ مسیرها (Routes) را باز می‌کند:

زبانه محتوا
متداول (Common) نمایهٔ مسیریابی فعال، راهبردهای دامنه و آینهٔ مجموعه‌قوانین.
ربایش (Hijack) منسوخ. به‌جای آن از حالتvpn (Tun Mode) استفاده کنید؛ DNS را ببینید.
Warp Cloudflare WARP؛ WARP را ببینید.
دی‌ان‌اس (DNS) سرورها و گزینه‌های DNS؛ DNS را ببینید.
مسیر (Route) نمایه‌های مسیریابی شما.

تنظیمات زبانهٔ متداول (Common):

تنظیم پیش‌فرض کارکرد
نمایه مسیریابی (Routing Profile) Default نمایهٔ مسیریابی فعال.
Default Domain Strategy خالی ترجیح IPv4 یا IPv6، وقتی Throne نشانی یک سرور یا سایتی را که مستقیم می‌رود پیدا می‌کند.
Resolve Domain Strategy خالی اگر تنظیم شود، Throne پیش از اجرای قوانین، نشانی IP هر دامنهٔ درخواستی را پیدا می‌کند تا قوانین IP هم بتوانند با دامنه‌ها منطبق شوند.
Remote Rule-set Mirror jsDelivr(Cloudflare) جایی که مجموعه‌قوانین و نمایه‌های ذخیره‌شده در GitHub از آن دانلود می‌شوند. GitHub آن‌ها را مستقیم دانلود می‌کند.

راهبردها عبارت‌اند از ipv4_only، ipv6_only، prefer_ipv4 و prefer_ipv6. در شبکه‌ای که IPv6 ندارد، ipv6_only را انتخاب نکنید.

دکمه‌های زبانهٔ مسیر (Route):

دکمه کارکرد
جدید (New) یک Structured profile، Raw profile یا Remote profile می‌سازد.
همزادسازی (Clone) از نمایهٔ انتخاب‌شده رونوشت می‌گیرد.
استخراج (Export) نمایهٔ انتخاب‌شده را به‌صورت لینک throne://route/ کپی می‌کند (Ctrl+C).
Import یک نمایه را از کلیپ‌بورد اضافه می‌کند (Ctrl+V).
Edit نمایهٔ انتخاب‌شده را باز می‌کند. دوبار کلیک روی آن هم همین کار را انجام می‌دهد.
از بین بردن (Delete) نمایهٔ انتخاب‌شده را حذف می‌کند (Del). آخرین نمایه را نمی‌توان حذف کرد.
Update Update selected یا Update all نمایه‌های راه‌دور را دوباره دانلود می‌کند.

تغییرات پنجرهٔ مسیرها با کلیک روی تایید (OK) ذخیره می‌شوند. اگر اتصالی در حال اجرا باشد، پنجرهٔ اصلی سپس پیام «Settings changed, restart to apply» (تنظیمات تغییر کرد؛ برای اعمال، دوباره راه‌اندازی کنید) را نشان می‌دهد. برای استفاده از قوانین جدید، همان‌جا روی Restart کلیک کنید.

نمایه‌های مسیریابی سه نوع‌اند: نمایه‌های ساخت‌یافته (structured) که آن‌ها را در Throne با قوانین ساده و قوانین پیشرفته ویرایش می‌کنید؛ نمایه‌های راه‌دور که از یک URL دانلود می‌شوند؛ و نمایه‌های خام که به‌صورت JSON برای sing-box نوشته می‌شوند. بیشتر افراد فقط به نمایه‌های ساخت‌یافته نیاز دارند.

برای ساختن یک نمایهٔ ساخت‌یافته:

  1. در زبانهٔ مسیر (Route)، روی جدید (New) ← Structured profile کلیک کنید.
  2. یک نام (Name) وارد کنید و Default outbound را انتخاب کنید.
  3. قوانین را در زبانهٔ پایه (Basic) یا زبانهٔ پیشرفته (Advanced) اضافه کنید.
  4. روی تایید (OK) کلیک کنید. در زبانهٔ متداول (Common)، این نمایه را به‌عنوان نمایه مسیریابی (Routing Profile) انتخاب کنید و سپس روی تایید (OK) کلیک کنید.

هر نمایهٔ جدید با یک قانون dns-hijack آغاز می‌شود. Throne در هر صورت همین مرحلهٔ DNS را به همهٔ نمایه‌های ساخت‌یافته اضافه می‌کند (DNS را ببینید)، پس می‌توانید این قانون را همان‌طور که هست رها کنید.

زبانهٔ Endpoints وقتی نمایان می‌شود که نمایه‌های OpenVPN یا OpenConnect داشته باشید. این زبانه آن‌ها را در کنار پروکسی شما و برای شبکه‌هایی که اعلام می‌کنند اجرا می‌کند؛ تونل تفکیکی را ببینید.

قوانین ساده

زبانهٔ پایه (Basic) هر نمایه چهار کادر دارد: مستقیم (Direct)، پروکسی (Proxy)، مسدود کردن (Block) و Warp-bypass. هر خط در یک کادر، ترافیک منطبق را به همان‌جا می‌فرستد. چگونه استفاده شود (How to use) خلاصهٔ کوتاهی از نحو نوشتن را نشان می‌دهد.

خط منطبق می‌شود با
domain:example.com فقط example.com.
suffix:example.com example.com و همهٔ زیردامنه‌های آن، مانند www.example.com.
keyword:example هر دامنه‌ای که example را در خود داشته باشد.
regex:^cdn[0-9]*\.example\.com$ دامنه‌هایی که با یک عبارت باقاعده منطبق باشند (نحو Go RE2).
ruleset:geosite-youtube همهٔ موارد یک مجموعه‌قوانین: یک نام داخلی یا URL یک فایل .srs.
ip:10.0.0.0/8 نشانی‌های IP در یک محدوده. یک نشانی تکی مانند 1.2.3.4 هم کار می‌کند.
processName:Telegram.exe اتصال‌های یک برنامه، بر اساس نام فایل.
processPath:C:\Program Files\App\app.exe اتصال‌های یک برنامه، بر اساس مسیر کامل.

قوانین نوشتن خط‌ها:

  • در هر خط یک مورد بنویسید. خط‌های خالی نادیده گرفته می‌شوند.
  • پیشوند را دقیقاً همان‌طور که نشان داده شده بنویسید، با رعایت حروف بزرگ و کوچک (processName، نه processname).
  • مقادیر domain:، suffix: و keyword: با حروف کوچک ذخیره می‌شوند.
  • نام فرآیند باید دقیقاً منطبق باشد، با رعایت حروف بزرگ و کوچک و پسوند .exe در Windows. زبانهٔ اتصال‌ها نام دقیق را نشان می‌دهد.
  • Throne خط‌ها را هنگام جابه‌جایی بین زبانه‌ها یا کلیک روی تایید (OK) بررسی می‌کند و خط‌هایی را که نمی‌تواند به کار ببرد، زیر «برخی قوانین اضافه نشدند» (Some rules could not be added) فهرست می‌کند. جابه‌جایی بین زبانه‌ها آن خط‌ها را حذف می‌کند. تایید (OK) تا وقتی آن‌ها را اصلاح نکنید ذخیره نمی‌کند.
نکته

قوانین فرآیند فقط ترافیکی را می‌بینند که به Throne می‌رسد. در حالت پروکسی سیستمی، برنامه‌هایی که پروکسی را نادیده می‌گیرند هرگز به آن نمی‌رسند؛ پس قوانین فرآیند را همراه با حالتvpn (Tun Mode) به کار ببرید. حالت TUN را ببینید.

مثال 1: همه‌چیز به‌جز سایت‌های داخلی از پروکسی، و مسدود کردن تبلیغات. Default outbound را روی proxy بگذارید. در مستقیم (Direct):

suffix:example.com
ruleset:geosite-ir
ruleset:geoip-ir

در مسدود کردن (Block):

ruleset:geosite-category-ads-all

به‌جای ir، کد کشور خودتان را بگذارید؛ برای نمونه cn یا ru.

مثال 2: فقط یک برنامه و یک سایت از پروکسی. Default outbound را روی direct بگذارید. در پروکسی (Proxy):

processName:Telegram.exe
suffix:example.org

ترتیب قوانین ساده

هر کادر به قوانین معمولی در زبانهٔ پیشرفته (Advanced) تبدیل می‌شود که به نام همان کادر نام‌گذاری شده‌اند، مانند Simple Address Bypass برای نشانی‌های کادر مستقیم (Direct) یا Simple Process Name Proxy برای برنامه‌های کادر پروکسی (Proxy). در یک نمایهٔ جدید، این قوانین به این ترتیب اضافه می‌شوند: مستقیم (Direct)، مسدود کردن (Block)، پروکسی (Proxy)، Warp-bypass. چون نخستین قانون منطبق برنده است، خطی در پروکسی (Proxy) اثری ندارد وقتی خطی گسترده‌تر در مستقیم (Direct) از قبل با همان ترافیک منطبق می‌شود.

برای ساختن یک استثنا، آن را در زبانهٔ پیشرفته (Advanced) بالا ببرید. برای نمونه، برای عبور دادن example.ir از پروکسی در نمایه‌ای که geosite-ir را مستقیم می‌فرستد:

  1. suffix:example.ir را به کادر پروکسی (Proxy) اضافه کنید.
  2. زبانهٔ پیشرفته (Advanced) را باز کنید و Simple Address Proxy را انتخاب کنید.
  3. آن‌قدر روی بالا بردن (Move Up) کلیک کنید تا این قانون بالاتر از قانونی قرار بگیرد که geosite-ir را در بر دارد.

قوانین پیشرفته

زبانهٔ پیشرفته (Advanced) همهٔ قوانین نمایه را به ترتیب نشان می‌دهد، همراه با جدید (New)، بالا بردن (Move Up)، پایین آوردن (Move Down) و از بین بردن (Delete). سمت چپ پنجره (در رابط انگلیسی، سمت راست) نام (Name) قانون و یک Preview از آن را به‌صورت JSON برای sing-box نشان می‌دهد.

برای افزودن یک قانون:

  1. روی جدید (New) کلیک کنید.
  2. یک Action انتخاب کنید.
  3. زبانهٔ + را باز کنید و ویژگی‌هایی را که لازم دارید تیک بزنید. هر ویژگی به یک زبانه تبدیل می‌شود. برداشتن تیک یک ویژگی، مقدار آن را پاک می‌کند.
  4. زبانه‌ها را پر کنید. در فهرست‌ها، هر مورد در یک خط نوشته می‌شود.
کنش کارکرد
route ترافیک منطبق را به outbound قانون می‌فرستد: proxy، direct، warp-bypass یا یک نمایهٔ ذخیره‌شده. قانون جدید تا وقتی outbound را تیک نزنید و گزینهٔ دیگری انتخاب نکنید، به direct می‌فرستد.
reject ترافیک منطبق را مسدود می‌کند. method و no_drop نحوهٔ آن را تغییر می‌دهند.
hijack-dns به پرس‌وجوهای DNS با DNS خود Throne پاسخ می‌دهد.
route-options گزینه‌هایی مانند override_address، override_port یا tls_spoof را تنظیم می‌کند و سپس با قوانین بعدی ادامه می‌دهد.
sniff پروتکل و دامنهٔ یک اتصال را تشخیص می‌دهد و سپس ادامه می‌دهد.
resolve نشانی IP دامنه را (با strategy) پیدا می‌کند و سپس ادامه می‌دهد.
bypass فقط در Linux، برای پیکربندی‌های پیشرفته. مستندات sing-box را ببینید.

برای مسدود کردن ترافیک در یک قانون پیشرفته، از reject استفاده کنید. نام block فقط به‌عنوان خروجی پیش‌فرض و به‌صورت کادر مسدود کردن (Block) وجود دارد.

ویژگی‌ها با چه چیزی منطبق می‌شوند
domain، domain_suffix، domain_keyword، domain_regex دامنهٔ درخواستی.
ip_cidr، ip_is_private نشانی مقصد؛ ip_is_private محدوده‌های خصوصی و محلی را پوشش می‌دهد.
rule_set نام‌های مجموعه‌قوانین داخلی یا URLهای .srs.
port، port_range پورت مقصد، برای نمونه 443 یا 1000:2000.
source_ip_cidr، source_ip_is_private، source_port، source_port_range مبدأ اتصال، برای نمونه دستگاه دیگری در شبکهٔ شما.
process_name، process_path، process_path_regex برنامه‌ای روی همین رایانه.
network، protocol، ip_version tcp، udp یا icmp؛ یک پروتکل تشخیص‌داده‌شده مانند tls، quic یا bittorrent؛ 4 یا 6.
inbound جایی که اتصال از آن وارد Throne شده است: mixed-in (پورت پروکسی) یا tun-in (حالت TUN).
wifi_ssid، wifi_bssid شبکهٔ Wi-Fi که به آن وصل هستید. در macOS در دسترس نیست.
package_name برنامه‌های Android. در دسکتاپ، قانونی که این ویژگی را دارد هرگز منطبق نمی‌شود.
invert مقدار true باعث می‌شود قانون زمانی منطبق شود که شرط‌هایش منطبق نباشند.

درون یک قانون، ویژگی‌های دامنه، IP و rule_set وقتی منطبق می‌شوند که هر یک از آن‌ها منطبق شود. ویژگی‌های دیگر، مانند port یا process_name، نیز باید منطبق شوند.

نکته‌ها:

  • استثناها اول می‌آیند. قانون مربوط به یک سایت را بالاتر از قانون مربوط به کل کشور یا فهرست قرار دهید.
  • قوانین فرآیند فقط برنامه‌هایی را می‌بینند که ترافیکشان به Throne می‌رسد. برای در بر گرفتن برنامه‌هایی که پروکسی سیستمی را نادیده می‌گیرند، از حالت TUN استفاده کنید؛ یادداشت زیر قوانین ساده را ببینید.
  • فرستادن ترافیک به یک سرور مشخص. outbound را تیک بزنید و یک نمایهٔ ذخیره‌شده را انتخاب کنید که به‌صورت [group] name نشان داده می‌شود. Throne آن نمایه را در کنار نمایه‌ای که آغاز کرده‌اید اجرا می‌کند. نمایه‌های هستهٔ اضافی (Extra Core) و پیکربندی‌های سفارشی کامل را اینجا نمی‌توان به کار برد.
  • قوانینی که نمی‌توانید ویرایش کنید. قانونی با نام «… route prefer» به زبانهٔ Endpoints تعلق دارد. فقط می‌توانید جابه‌جایش کنید.

مجموعه‌قوانین

مجموعه‌قوانین (rule-set) فهرستی از دامنه‌ها یا محدوده‌های IP است که در یک فایل جداگانه نگهداری می‌شود. از آن در یک قانون ساده (ruleset:<name>) یا در ویژگی rule_set یک قانون پیشرفته استفاده کنید.

  • نام‌های داخلی. Throne بیش از 2000 مجموعه‌قوانین را با نام می‌شناسد. نام‌هایی که با geosite- شروع می‌شوند دامنه‌ها را در خود دارند، برای نمونه geosite-youtube، geosite-cn یا geosite-category-ads-all. نام‌هایی که با geoip- شروع می‌شوند محدوده‌های IP را در خود دارند، برای نمونه geoip-ir، geoip-telegram یا geoip-private. وقتی در کادر یک قانون ساده یا در زبانهٔ rule_set عبارت ruleset: را تایپ می‌کنید، Throne نام‌های منطبق را پیشنهاد می‌دهد.
  • فایل‌های خودتان. URL هر مجموعه‌قوانین باینری sing-box کار می‌کند، برای نمونه ruleset:https://example.com/lists/my-sites.srs. نام فایل در URL باید .srs را در خود داشته باشد.

Throne مجموعه‌قوانین هر نمایه را هنگام آغاز آن نمایه دانلود می‌کند و در حافظهٔ نهان (cache) هسته نگه می‌دارد. مسیریابی (Routing) ← Update Rule-Sets نسخه‌های تازه را دانلود می‌کند. این گزینه وقتی اتصالی در حال اجراست در دسترس است و اعلام می‌کند چند مجموعه‌قوانین را تازه کرده است.

مجموعه‌قوانین داخلی روی GitHub نگهداری می‌شوند. اگر GitHub در شبکهٔ شما مسدود یا کُند است، تنظیمات مسیریابی (Routing Settings) ← متداول (Common) ← Remote Rule-set Mirror را تغییر دهید. این آینه (mirror) برای فهرست AdBlock و نمایه‌های مسیریابی ذخیره‌شده در GitHub نیز به کار می‌رود. URLهای .srs خودتان همیشه همان‌طور که نوشته شده‌اند استفاده می‌شوند.

نمایه‌های راه‌دور

نمایهٔ راه‌دور یک نمایهٔ ساخت‌یافته است که Throne آن را از یک URL دانلود می‌کند. نمایه‌هایی که با Download Profiles دریافت می‌شوند، نمایهٔ راه‌دور هستند. یک ارائه‌دهنده نیز می‌تواند با یک لینک throne://remoteroute/ چنین نمایه‌ای به شما بدهد.

برای افزودن آن به‌دست خودتان:

  1. در زبانهٔ مسیر (Route)، روی جدید (New) ← Remote profile کلیک کنید.
  2. یک نام (Name) و URL را وارد کنید. این نشانی می‌تواند یک لینک throne://route/، متن Base64 آن یا JSON نمایه را ارائه دهد.
  3. روی Preview کلیک کنید تا نمایه را بدون تغییر چیزی ببینید، یا روی Fetch تا قوانینش همین حالا بارگذاری شوند.
  4. برای به‌روز نگه داشتن نمایه، Auto update را تیک بزنید و سپس روی تایید (OK) کلیک کنید.

URL باید یک نمایهٔ ساخت‌یافته ارائه دهد. نمایه‌های خام نمی‌توانند نمایهٔ راه‌دور باشند.

به‌روزرسانی خودکار به دو چیز نیاز دارد: گزینهٔ Auto update خود نمایه، و تنظیمات (Settings) ← تنظیمات پایه (Basic Settings) ← اشتراک (Subscription) ← Routing profiles auto update. دومی به‌طور پیش‌فرض خاموش است. بازهٔ آن بر حسب دقیقه است (پیش‌فرض 1440، یعنی روزی یک بار)؛ مقادیر کمتر از 30 آن را خاموش می‌کنند. زبانهٔ Runtime Stats مقدار Next remote route update را نشان می‌دهد. برای به‌روزرسانی فوری، از Update در زبانهٔ مسیر (Route) استفاده کنید.

به‌روزرسانی، قوانین و خروجی پیش‌فرض را با نسخه‌های دانلودشده جایگزین می‌کند، پس تغییراتی که خودتان در نمایه داده‌اید از بین می‌روند. برای تغییر ایمن یک نمایهٔ راه‌دور، با همزادسازی (Clone) از آن رونوشت بگیرید، رونوشت را باز کنید و تیک Auto update را بردارید. به‌روزرسانی، اتصال در حال اجرا را دوباره راه‌اندازی نمی‌کند: قوانین جدید دفعهٔ بعد که یک نمایه را آغاز کنید به کار می‌روند.

نمایه‌های خام

نمایهٔ خام یک شیء کامل route برای sing-box به‌صورت JSON است. وقتی به قابلیت‌هایی از sing-box نیاز دارید که ویرایشگر قوانین ارائه نمی‌دهد، از آن استفاده کنید.

در زبانهٔ مسیر (Route)، روی جدید (New) ← Raw profile کلیک کنید. ویرایشگر، JSON را بررسی می‌کند و دکمهٔ Format JSON دارد. خروجی‌ها به‌صورت عدد نوشته می‌شوند:

عدد خروجی
-1 proxy
-2 direct
-5 warp-bypass
شناسهٔ یک نمایه یک نمایهٔ ذخیره‌شده. پس از "outbound": یا "final":، ویرایشگر نمایه‌های شما را با نامشان پیشنهاد می‌دهد و عدد را درج می‌کند.

اگر final وجود نداشته باشد، Throne از proxy استفاده می‌کند. نام‌های مجموعه‌قوانین داخلی برای شما تعریف نشده‌اند: ورودی‌های rule_set خودتان را به JSON اضافه کنید. Throne همچنین مرحلهٔ DNS را که نمایه‌های ساخت‌یافته به‌طور خودکار دریافت می‌کنند، اضافه نمی‌کند. برای حالت TUN، قوانینتان را این‌گونه آغاز کنید:

{
  "rules": [
    { "action": "sniff" },
    { "protocol": "dns", "action": "hijack-dns" },
    { "domain_suffix": ["example.com"], "outbound": -2 }
  ],
  "final": -1
}

Prevent modifications شیء را دقیقاً همان‌طور که نوشته شده به کار می‌برد؛ Throne فقط عددهای خروجی را به برچسب (tag) تبدیل می‌کند. در این حالت Throne هیچ چیزی از خودش اضافه نمی‌کند، پس DNS، نمایه‌های Xray، زنجیره‌ها و قابلیت‌های دیگر ممکن است از کار بیفتند. فقط اگر sing-box را به‌خوبی می‌شناسید از آن استفاده کنید.

Enable AdBlock، Enable DNS Routing و گزینه‌های Append زبانهٔ اتصال‌ها با نمایه‌های خام کار نمی‌کنند. Throne برای Android نمی‌تواند از نمایه‌های خام استفاده کند.

زبانهٔ اتصال‌ها

زبانهٔ اتصال‌ها (Connections) در پایین پنجرهٔ اصلی، اتصال‌های باز را به تفکیک برنامه فهرست می‌کند. برای هر اتصال، مقصد، پروتکل، خروجیِ استفاده‌شده و ترافیک آن را نشان می‌دهد. این سریع‌ترین راه برای دیدن مسیر یک سایت و افزودن قانون برای آن است.

روی یک اتصال راست‌کلیک کنید:

گزینهٔ منو کارکرد
Append "<host>" to → Direct / Proxy / Block suffix:<host> را به کادر متناظر در نمایهٔ مسیریابی فعال اضافه می‌کند. برای یک نشانی IP، ip:<address> را اضافه می‌کند.
Append process "<name>" to → Direct / Proxy / Block processName:<name> را به همان کادر اضافه می‌کند.
Copy Destination، Copy Process Name مقدار را کپی می‌کند.
Close connection اتصال را می‌بندد.

پس از افزودن یک قانون، در اعلان «Settings changed, restart to apply» (تنظیمات تغییر کرد؛ برای اعمال، دوباره راه‌اندازی کنید) روی Restart کلیک کنید. خط جدید به قانون سادهٔ موجودِ همان کادر افزوده می‌شود. اگر آن کادر خالی بوده باشد، قانونش به انتهای فهرست اضافه می‌شود؛ جایی که یک قانون گسترده‌تر در بالای آن همچنان می‌تواند زودتر منطبق شود. ترتیب را در زبانهٔ پیشرفته (Advanced) بررسی کنید.

گزینه‌های Append وقتی غیرفعال‌اند که نمایهٔ مسیریابی فعال خام باشد، با Prevent modifications قفل شده باشد، یا یک نمایهٔ راه‌دور با Auto update روشن باشد. برای دیدن دلیل، نشانگر ماوس را روی گزینه نگه دارید. برای یک نمایهٔ راه‌دور، ابتدا همان‌طور که در نمایه‌های راه‌دور آمده، از آن رونوشت بگیرید.

این زبانه به تنظیمات (Settings) ← تنظیمات پایه (Basic Settings) ← استایل (Style) ← آمار اتصال (Connection statistics) ← فعال کردن (Enable) نیاز دارد که به‌طور پیش‌فرض روشن است.

AdBlock

مسیریابی (Routing) ← Enable AdBlock تبلیغات را در هر نمایهٔ مسیریابی‌ای که فعال باشد مسدود می‌کند. Throne یک قانون مسدودسازی برای یک مجموعه‌قوانین عمومی ضدتبلیغات (adblocksingbox از پروژهٔ 217heidai/adblockfilters) اضافه می‌کند. این قانون پیش از قوانین route خودتان اجرا می‌شود، پس تبلیغات هم برای ترافیک مستقیم و هم برای ترافیکی که از پروکسی می‌گذرد مسدود می‌شوند. روشن یا خاموش کردن AdBlock، اتصال در حال اجرا را دوباره راه‌اندازی می‌کند.

  • AdBlock با نمایه‌های ساخت‌یافته و راه‌دور کار می‌کند، نه با نمایه‌های خام.
  • اگر سایتی از کار افتاد، AdBlock را خاموش کنید تا ببینید آیا فهرست آن را مسدود می‌کند.
  • برای مسدود کردن تبلیغات فقط در یک نمایه، به‌جای آن ruleset:geosite-category-ads-all را در کادر مسدود کردن (Block) همان نمایه بگذارید.

اشتراک‌گذاری نمایه‌ها

برای اشتراک‌گذاری یک نمایهٔ مسیریابی، آن را در زبانهٔ مسیر (Route) انتخاب کنید و روی استخراج (Export) کلیک کنید (یا در فهرست، Ctrl+C را فشار دهید). Throne یک لینک throne://route/ کپی می‌کند. این لینک را برای هر کسی که می‌خواهید بفرستید.

برای وارد کردن یک نمایه:

  • در تنظیمات مسیریابی. لینک را کپی کنید، زبانهٔ مسیر (Route) را باز کنید و روی Import کلیک کنید (یا در فهرست، Ctrl+V را فشار دهید). Throne می‌پرسد «Import routing profile … from the clipboard?» (نمایهٔ مسیریابی … از کلیپ‌بورد وارد شود؟). اگر کلیپ‌بورد هیچ نمایه‌ای نداشته باشد، کادری باز می‌شود که می‌توانید در آن یک لینک مسیر Throne، یک لینک مسیر راه‌دور، متن Base64 یا یک آرایهٔ JSON از قوانین را جای‌گذاری کنید. نمایهٔ واردشده در زبانهٔ متداول (Common) نیز انتخاب می‌شود، پس با کلیک روی تایید (OK) فعال می‌شود.
  • از هر جای دیگر. روی لینک کلیک کنید، یا آن را کپی کنید و در پنجرهٔ اصلی Ctrl+V را فشار دهید. Throne می‌پرسد «Add this routing profile?» (این نمایهٔ مسیریابی اضافه شود؟) و آن را بدون فعال کردن اضافه می‌کند.

آنچه لینک در خود دارد:

  • نام، خروجی پیش‌فرض و قوانین.
  • قوانینی که ترافیک را به یک نمایهٔ ذخیره‌شده می‌فرستند، با نام به آن اشاره می‌کنند. در رایانهٔ دیگر، Throne از نمایه‌ای با همان نام استفاده می‌کند، یا اگر چنین نمایه‌ای نباشد از proxy، و این را به شما اطلاع می‌دهد.
  • نقطه‌های پایانی VPN (VPN endpoints)، بدون اطلاعات ورودشان. وقتی چنین لینکی را وارد می‌کنید، Throne نمایه‌های OpenVPN یا OpenConnect را پیش از پرسیدن «Add this routing profile?» می‌سازد و اگر لغو کنید، آن‌ها را نگه می‌دارد.

برای قالب لینک، لینک‌های عمیق را ببینید.

در Android

Throne برای Android همین نمایه‌های مسیریابی، قوانین و مجموعه‌قوانین را دارد. مسیریابی (Routing) را از منوی کناری باز کنید؛ برای فعال کردن یک نمایه، روی آن بزنید. تفاوت‌ها:

  • قوانین برنامه. ویرایشگر قوانین یک فیلد Apps دارد که با برنامه‌های Android منطبق می‌شود. دسکتاپ نمی‌تواند برنامه‌های Android را ببیند، پس در آنجا قانونی با شرط برنامه هرگز منطبق نمی‌شود. Android هنگام صادر کردن نمایه‌ای با چنین قوانینی، یادداشتی نشان می‌دهد.
  • قوانین Wi-Fi. Wi-Fi SSID و Wi-Fi BSSID به دسترسی به موقعیت مکانی دقیق با تنظیم «Allow all the time» (همیشه مجاز) و روشن بودن موقعیت مکانی نیاز دارند، چون در غیر این صورت Android نام Wi-Fi را پنهان می‌کند. Throne هنگام ذخیرهٔ چنین قانونی این دسترسی را درخواست می‌کند. اگر دسترسی وجود نداشته باشد، اعلان «Wi-Fi rules are inactive» (قوانین Wi-Fi غیرفعال‌اند) نمایش داده می‌شود.
  • نمایه‌های خام. Android لینک‌های خام throne://route/ را رد می‌کند («raw routing profiles are not supported on Android»، یعنی نمایه‌های مسیریابی خام در Android پشتیبانی نمی‌شوند). نمایه‌های خامِ یک نسخهٔ پشتیبان دسکتاپ نگه داشته می‌شوند اما قابل استفاده نیستند («Raw (Throne desktop) · read-only»، یعنی خام، از Throne دسکتاپ، فقط‌خواندنی).
  • نقطه‌های پایانی VPN در یک لینک واردشده، با یک هشدار حذف می‌شوند.
  • جابه‌جایی سریع. در صفحهٔ پیکربندی (Profiles)، منو (⋮) ← Routing profile نمایه‌های مسیریابی شما را فهرست می‌کند. همین پنجره یک دکمهٔ Enable WARP / Disable WARP دارد.
  • لینک‌ها. لینک throne://route/ نمایه را اضافه می‌کند اما آن را فعال نمی‌کند.

Download profiles، Update rule-sets و نمایه‌های راه‌دور همانند دسکتاپ کار می‌کنند. AdBlock و Auto update remote profiles در تنظیمات (Settings) ← Routing قرار دارند.
